# mosaic-mind 종합 보고서 (2026-10-10)

## 1. 목표와 가설

**목표**: 노트북 한 대(RTX 5070 Laptop 8GB, RAM 31GB)에서 "작은 AGI의 시작점"을 만든다. 합계 8B급 메모리 예산 안에서, 작고 특화된 부품들을 엮어 Gemma 4급 단일 모델보다 낫고 AGI 특성(판단, 공부, 생각, 성장)을 보여 준다.

**가설 (MK1)**: 한 모델을 키우는 대신 작은 특화 부품을 엮는다. LLM은 언어 모델답게 **말하기만** 하고, 판단·기억·생각·배움은 다른 부품이 맡는다("베가펑크처럼 뇌를 나눈다").

**시험 규칙**: 외부 공개 시험, 봉인셋은 한 번만 연다, 튜닝은 개발용에서만, 판정 기준은 열기 전에 커밋, 짝지은 부트스트랩 95% 구간, 실패도 그대로 기록.

## 2. 지금의 구조 (MK1 v3)

```
입력 → 칠판 (칸 + 누가·무엇을·몇 초)
  1 형태 보기    격자 / 문서+질문 / 라벨 흐름 (입력 구조로, 고정 규칙)
  2 싼 위성 먼저  읽기 위성(0.28B), 단계별 선택기, 격자 탐색기(신경망 없음), 자라는 부품(bge-large 0.34B 위)
  3 가치 판단    말하기 위성(Gemma 4 E2B)이 결정을 바꿀 수 있을 때만 부름
  4 보정         시험 밖 데이터로 배운 보정기 → P(맞음), P(답할 수 있음)
  5 결정         시험 점수 규칙의 기대값 (문서: 2·P(맞음) − 1 > 1 − P(답할 수 있음)이면 답)
  6 말하기       말하기 위성이 말로 (또는 "모름")
  7 배우기       피드백 → 자라는 부품, 세는 중재자, 맥락 추론(새 부품 만들기, 쪼개기, 되돌리기)
```
메모리: E2B(Q4) + 읽기 위성 + 선택기 + bge-large 등, 합계 Gemma 4 E4B 하나보다 작다.

## 4. 가설 판정 (냉정하게)

| 주장 | 상태 | 근거 |
|---|---|---|
| 엮으면 같은 LLM 혼자보다 낫다 | **지지됨** | 위 표, MuSiQue 외 전부 |
| 엮으면 더 큰 단일 모델을 이긴다 | **부분** | 이김 4, 비김 4, 짐 2 |
| LLM은 말만, 판단은 다른 부품 | **지지됨** | 거절·검증·탐색·학습이 점수를 올림 |
| 판단 (모르면 멈춤) | **지지됨, 단서** | RGB 거절. 섞인 시험의 문서 질문에서는 보정 결정의 이득이 봉인 데이터로 옮겨 가지 않음 |
| 공부·성장 (피드백으로 배움) | **지지됨** | 학습 곡선이 계속 오름, E4B는 예시 16개에서 멈춤 |
| 생각 | **반반** | ARC 이김(정확한 검증기 있음), MuSiQue 짐(없음) |
| 하나의 시스템 | **됨** | 섞인 흐름에서 시험별 점수 재현, 봉인 섞인 시험 |
| 스스로 자라기 | **지지됨** | 과제 이름 없이 맥락을 추론해 자람. 첫 봉인 자라기 끔보다 +0.110(E4B와 비김), 느린 쪼개기 뒤 sealed2에서 E4B를 이김(+0.063) |

**한 줄**: 작은 특화 부품을 엮는 쪽이 **판단, 새로 배우기, 검증 가능한 생각, 스스로 자라기**에서 더 큰 단일 모델과 비기거나 이긴다는 것은(자라기는 sealed2에서 이김) 외부 봉인 시험으로 지지된다. **넓은 언어 추론과 사전 지식**에서는 아직 큰 LLM이 앞선다.

## 5. 원리 (여러 시험에서 같은 방향으로 나온 것)

1. **계산을 더 쓰는 것은 정확한 검증기가 있을 때만 이득이다.** ARC는 프로그램을 예시에 다시 돌려 확인할 수 있어서 이겼고, MuSiQue는 그런 확인이 없어서 졌다(문헌: Snell 외 2025, Huang 외 2024).
2. **표는 독립된 출처만 센다.** 같은 LLM의 여러 답은 독립이 아니다.
3. **엮기는 "아는 것"이 아니라 "새로 배우는 것"에서 이긴다.** 사전 지식이 필요한 이름 라벨은 큰 LLM이 앞서고, 기호 라벨은 피드백으로 배우는 부품이 앞선다.
4. **작은 모델의 자기 확신은 믿지 않는다.** 바깥 특징으로 배운 보정기가 낫다.
5. **노트북 제약은 설계 원칙이다.** 싼 위성 먼저, 말하기 위성은 필요할 때만(MuSiQue에서 E2B 호출 최대 4번 → 1.4번).

## 6. 실패와 정정 (기록)

- 첫 MuSiQue 다단계 파이프라인: 작은 LLM의 질문 쪼개기가 오류를 쌓아 이득 없음.
- RGB 첫 판: 위성 답을 다시 조립하다 통합 능력을 잃음 → 말하기 위성이 답하고 위성은 통과·거부만.
- TREC 라벨 순서 버그, 이름 라벨 해석의 대소문자 버그(개발용에서 발견, 모든 시스템 다시 채점).
- "중심 맞추기 +0.04"는 실제로 정규화 효과였음(정정).
- v3의 RGB 격차를 "구해 내기가 없어서"라고 잘못 설명함 → 데이터로 확인하니 너무 조심하는 것(기저율 이동)이 원인.
- llama.cpp 프롬프트 캐시가 출력을 바꾸는 비결정성 → 모든 호출에서 끔, 신호 다시 기록.
- 봉인 섞인 시험에서 기록용 칸 누락으로 v3가 멈춤(고치고 이어 돌림, 판단 로직 변화 없음).
- "부품 5개 = 과제 5개"는 개수만 맞았음(같은 영역 과제가 부품을 함께 씀) → 느린 쪼개기로 고침(순도 0.60 → 0.85, 대신 부품 9개로 더 쪼갬).

## 7. 남은 빈칸과 다음

1. **넓은 언어 추론** (MuSiQue): 작은 독해기로는 4B급 추론을 못 따라감. 검증기 없는 생각을 어떻게 할지가 가장 큰 숙제.
2. **보정기의 분포 이동**: 시험 밖 데이터로 배운 확률이 새 시험으로 덜 옮겨 감.
3. **배우는 법 배우기**: ARC 기본 동작 90개, 위성 목록, 입력 종류 규칙은 사람이 만들었다. 이것을 경험으로 넓히는 것이 다음 큰 단계.
4. **봉인 데이터 고갈**: RGB, ARC-AGI-1, SST-2, TREC는 다 썼다. 다음 판정에는 새 공개 시험이 필요하다.
