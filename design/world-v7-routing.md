# 규칙 세계 v7: 사령탑 (스스로 어떤 부품을 부를지 정하기)

작성일: 2026-10-08
관련: [부품 연결 v4](world-v4-composite.md), [생각 루프 v3](world-v3-thinking.md), [말투 세계 v2-H](world-v2h-tone-cues.md)

## 질문

정답 라벨 없이 **결과 점수만 보고** 어떤 부품을 부를지 배울 수 있는가? 학습 때는 **부품 하나만** 필요하던 경험으로, 시험에서 **처음 보는 조합**(두 부품을 이어야 하는 문제)을 스스로 만들어 내는가?

## 처음 설계의 구멍 (구현 전에 발견)

처음에는 사령탑이 문제의 겉모양(질문한 문, 안내판 내용의 요약)을 보고 부품마다 켤지 말지 정하게 하려 했다. 그런데 학습 문제에서는 "고리 끝 문을 묻는다"와 "안내판이 기준 문의 열쇠를 알려 준다"가 항상 같이 나온다. 그러면 생각 루프를 켜야 하는 이유가 둘 중 무엇인지 데이터로 구별할 수 없다. 처음 보는 "둘 다" 문제(고리 끝을 묻지만 기준 문 열쇠는 사람들 말로만 알 수 있음)에서 엉뚱한 근거로 판단할 수 있다. **겉모양 라우팅은 이런 혼동을 피할 수 없다.**

## 수정한 설계: "모자란 것"을 보고 부르기

1. **생각 루프가 먼저 생각한다**(항상): 안내판 문장만으로 고리를 따라간다.
2. **사령탑이 생각 루프의 상태를 본다**: 기준 문(빨강/파랑/초록) d마다 다음을 본다.
   - 질문한 문과 생각 루프의 연결로 이어져 있는가
   - d가 질문한 문 자체인가
   - 생각 루프가 d의 열쇠를 아는가(확신도)
   - 질문한 문의 답을 이미 아는가(확신도)
   그리고 **"d에 대해 신뢰 부품에 물으면 점수가 얼마나 오를까"**를 예측한다.
3. 예측 이득이 비용(0.05)보다 큰 기준 문마다 신뢰 부품에 묻는다. 신뢰 부품의 결론은 연결 장치(4단계)를 거쳐 생각 루프에 사실로 들어가고, 생각 루프가 다시 생각한다.

- 학습: 학습 문제마다 기준 문 하나씩 "물었을 때"를 실제로 돌려 보고, 점수 변화로 이득을 회귀한다(2단계 호기심 머리와 같은 방식). 정답 라우팅은 가르치지 않는다.
- "신뢰만" 문제(질문 문 = 기준 문, 열쇠 모름)와 "둘 다" 문제(고리로 이어진 기준 문, 열쇠 모름)는 사령탑 입장에서 **같은 종류의 상황**(이어져 있고 열쇠를 모름)이다. 그래서 일반화가 원리적으로 가능하다.
- 사람이 준 틀: 부품을 부르는 단위(기준 문마다 묻기), 생각 루프의 연결 그래프에서 "이어져 있는가"를 계산하는 것(연결 성분). 무엇을 언제 부를지는 결과에서 배운다.

## 세계 (`world7/routing.py`)

v2-H 세션(사람 4명, 숨은 정확도, 말투, 매 문제 피드백)과 v4 안내판 고리를 쓴다. 문제 종류는 세 가지이고, 종류는 알려 주지 않는다.

| 종류 | 질문 | 기준 문 열쇠 | 필요한 부품 |
|---|---|---|---|
| 신뢰만 (T) | 기준 문(닻) 자체 | 사람들 말로만 | 신뢰 |
| 생각만 (C) | 닻에서 시작하는 고리 끝 문 (L = 1–3) | 안내판이 알려 줌 | 생각 |
| 둘 다 (TC) | 고리 끝 문 | 사람들 말로만 | 신뢰 → 생각 |

- 모든 종류에서 사람들이 말하고, 모든 기준 문에 고리가 붙는다. 닻이 아닌 기준 문은 각각 확률 0.5로 안내판이 열쇠를 알려 준다. 그래서 "안내판에 사실이 있다"만으로는 종류를 알 수 없다.
- 학습: T와 C만(반반). 시험: T, C, TC 각 1/3.
- 점수: 맞으면 +1, 틀리면 −1, 모름 0, 신뢰 부품에 한 번 물을 때마다 −0.05. 생각 루프는 모든 방식에서 똑같이 돌므로 비용에 넣지 않는다.

## 부품 (모두 얼림)

- 신뢰 부품: 1단계(seed s), 연결 장치: 4단계 성장형(seed s), 생각 루프: 3단계(seed s+3). seed s = 42, 43, 44.

## 비교

- **통째 사령탑**: 같은 상태 정보(기준 문별 특징을 모아 펼친 것)를 보고 계획 하나를 고른다. 계획은 {안 물음, 질문 문에 대해 물음, 기준 문 셋 다 물음}이다. 학습 때 "셋 다 물음"이 최선인 경우는 없다(T에서는 질문 문만 물으면 되고, C에서는 안 물어도 된다).
- 참고: 이상적 라우팅(닻에 대해서만 묻기, 구조를 앎), 항상 안 물음, 항상 셋 다 물음, 사후 최선(실제 결과를 아는 상한).

## 미리 적어 두는 판정 (seed 42–44)

- **졸업**: 처음 보는 TC 문제에서
  - (a) 사령탑 점수 ≥ 이상적 라우팅의 0.9배 (seed 평균)
  - (b) 사령탑 − 통째 사령탑 ≥ +0.1 (seed 3개 모두 양수)
  - (c) T와 C에서 사령탑 점수 ≥ 이상적 라우팅 − 0.03 (쓸데없이 묻지 않음)
- 함께 볼 것: 문제 종류별로 물은 기준 문의 수, 닻이 아닌 문에 물은 비율(낭비).

## 1차 실행과 수정 (2026-10-08)

- 1차(seed 42, 시험 세션 +300): 사령탑 특징에 "d가 질문한 문인가"를 넣었다. 결과는 T 0.395 = 이상적, C 1.000 = 이상적, **TC 0.000** (이상적 0.396). 사령탑이 TC에서 한 번도 묻지 않았다. 통째 사령탑도 0.000이다. 결과는 `archive/world-v7_router_seed-42_identity-feature.json`에 있다.
- 원인: 학습(T)에서는 "이어져 있고 열쇠를 모름"과 "질문한 문 자체"가 항상 같이 나온다. 사령탑은 정체 특징("질문한 문이면 묻는다")을 잡았다. 설계에서 피하려던 혼동이 더 작은 규모로 다시 생겼다. **모자란 것만 봐야 하는데 정체를 알려 주는 특징을 섞었다.**
- 수정: 사령탑 특징에서 "질문한 문인가"를 뺐다. 남은 특징은 [이어져 있는가, d의 열쇠 확신도, 답 확신도]다. 통째 사령탑도 같은 특징 9개를 본다. 다만 통째 사령탑의 계획 "질문한 문에 묻기"를 정의하는 데에는 질문한 문 정보가 쓰인다.
- 1차 시험을 봤으므로, 수정판은 **새 시험 세션**(v2-H 시험 seed + 400)으로 평가한다. 판정 기준은 그대로다.

- 해석과 한계:

  - "이어져 있는가"는 생각 루프가 배운 연결 그래프에서 사람이 짠 계산(연결 성분)으로 뽑는다. 이 부분은 틀이다.
