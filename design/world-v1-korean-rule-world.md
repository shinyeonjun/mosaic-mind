# 규칙 세계 v1: 지능 구조 비교용 작은 세계와 점수판

작성일: 2026-10-06
상태: Phase 1 생성기·해결기·지름길 검사·점수판 구현 완료, L1·P1 대기

## 왜 이걸 먼저 만드나

목표는 사람을 흉내 내는 것이 아니라, 정해진 계산·메모리·시간 예산에서 **가장 잘 판단하는 구조**를 찾는 것이다. "이상적인 구조"는 설계로 정해지지 않고 측정으로 정해진다. 그래서 구조보다 먼저 다음 두 가지를 고정한다.

1. **세계**: 한국어로 사실이 주어지고, 정정·방해·부족한 정보가 섞이는 작은 환경
2. **점수판**: 어떤 구조든 같은 기준으로 비교하는 지표

이후의 모든 후보는 같은 세계와 점수판으로 비교한다. 후보에는 작은 LLM 단독 풀이, 전문 모델 조합, 학습된 지휘자가 포함된다.

## 실험 001–010에서 가져오는 교훈

- **지름길 검사를 필수로 둔다.** 003–005에서는 훈련 데이터에서 "문 번호 → 열쇠"라는 지름길이 생겼고, 시험 데이터는 그 대응을 뒤집었다. 그래서 일반 사례 정확도가 찍기(33%)보다 낮은 3–11%가 나왔다. v1에서는 분할을 만들 때마다 지름길 기준선을 자동으로 돌리고, 하나라도 찍기 수준을 넘으면 그 분할을 쓰지 않는다.
- **모델 선택용 검증셋도 처음 보는 조합으로 만든다.** 007–010은 훈련 규칙으로 만든 검증셋으로 체크포인트를 골랐다. 그래서 010에서 처음 보는 조합의 규칙 해독률이 0%라는 사실을 학습 중에 볼 수 없었다.
- **알아듣기와 생각하기를 분리해 평가한다.** 같은 문제를 정답 구조 입력과 실제 파서 입력 두 조건으로 풀게 해서, 파싱 실패와 판단 실패를 구분한다.

## 세계의 기본 규칙

- 문 3개(빨간 문, 파란 문, 초록 문)와 열쇠 3개(빨간 열쇠, 파란 열쇠, 초록 열쇠)가 있다. 시험용으로 처음 보는 이름(예: 보라 문, 금색 열쇠)을 따로 둔다.
- **세계 공리**: 모든 문은 정확히 한 종류의 열쇠로 열린다. 이 공리는 에피소드 시작 때 문장으로 주어진다.
- 사실을 말하는 **출처**는 관리인, 안내판, 지나가던 사람 세 종류다.
- Phase 1의 판단 규칙은 에피소드마다 문장으로 주어지며, 정답 해결기(`world/solver.py`)가 이 규칙을 그대로 구현한다.
  - 반박되지 않은 말은 믿는다.
  - 같은 사람이 정정하면 정정한 말을 따른다.
  - 말이 서로 다르면 관리인 > 안내판 > 지나가던 사람 순으로 믿는다. 덜 믿을 만한 출처가 "정정"해도 더 믿을 만한 출처의 말을 덮지 못한다.
  - 여러 문이 같은 열쇠를 쓸 수 있다. 그래서 다른 문의 정보로는 질문한 문의 열쇠를 추론할 수 없다.
- Phase 4에서는 출처 신뢰 순서를 숨기고, 여러 에피소드를 거치며 스스로 알아내게 한다.

## 에피소드 형식

에피소드 하나는 4–10개의 한국어 발화와 마지막 질문 하나로 이루어진다. 정답은 열쇠 이름 또는 `모름`이다.

```json
{
  "episode_id": "v1-p1-000123",
  "phase": 1,
  "world_rules": "모든 문은 정확히 한 종류의 열쇠로 열린다. 관리인 > 안내판 > 지나가던 사람 순으로 믿을 만하다.",
  "utterances": [
    {"source": "관리인", "text": "빨간 문은 파란 열쇠로 열려."},
    {"source": "관리인", "text": "아, 내가 잘못 말했다. 빨간 문은 초록 열쇠야."}
  ],
  "question": "빨간 문은 무슨 열쇠로 열어?",
  "answer": "초록 열쇠",
  "gold_events": [
    {"step": 0, "type": "assert", "door": "빨간", "key": "파란", "polarity": true, "source": "관리인"},
    {"step": 1, "type": "correct", "door": "빨간", "key": "초록", "polarity": true, "source": "관리인"}
  ],
  "tags": ["correction"],
  "split_keys": {"template_ids": ["assert.03", "correct.07"], "composition": "red|blue->green", "entity_set": "base"}
}
```

`gold_events`는 정답 구조 조건에서만 에이전트에게 주고, 실제 파서 조건에서는 숨긴다. `split_keys`는 분할과 지름길 검사에 쓴다.

## 능력별 사례 유형

| 능력 | 사례 유형 | 정답을 내는 방법 | 도입 단계 |
|---|---|---|---|
| 알아듣기 | 같은 사실의 다양한 표현 (반말/존댓말, 어순, "~래", "~라더라") | 표현에 상관없이 같은 사실로 읽기 | 1 |
| 기억하기 | 정정 ("아까 건 틀렸어", "정정할게") | 최신 정정 반영 | 1 |
| 기억하기 | 방해 정보 (다른 문 얘기, 잡담) | 무관한 내용 무시 | 1 |
| 판단하기 | 부정과 소거 ("빨간 열쇠로는 안 열려" ×2) | 공리로 남은 하나 추론 | 1 |
| 판단하기 | 정보 없음 | `모름` | 1 |
| 판단하기 | 출처 충돌 (지나가던 사람 vs 관리인) | 믿을 만한 출처 채택 | 1 |
| 궁금해하기 | 정보가 부족하지만 질문 가능 | 관리인에게 질문(비용 있음) 후 답 | 2 |
| 생각해보기 | 열쇠가 쓰면 사라지고 문이 연결된 경로 | 행동 전에 결과를 예측해 순서 정하기 | 3 |
| 공부하기 | 출처 신뢰도와 숨은 경향이 에피소드 간 유지됨 | 경험으로 신뢰도 추정, 질문 수 감소 | 4 |
| 공부하기 | 중간에 세계 규칙이 바뀜 | 바뀐 걸 감지하고 낡은 믿음 고치기 | 4 |

### 예시 (Phase 1)

**정정**
> 관리인: 빨간 문은 파란 열쇠로 열려.
> 관리인: 초록 문은 빨간 열쇠로 열려.
> 관리인: 아, 내가 잘못 말했다. 빨간 문은 초록 열쇠야.
> 질문: 빨간 문은 무슨 열쇠로 열어? → **초록 열쇠**

**부정과 소거**
> 안내판: 파란 문은 빨간 열쇠로는 안 열린다.
> 지나가던 사람: 오늘 날씨 좋네요.
> 안내판: 파란 문은 초록 열쇠로도 안 열린다.
> 질문: 파란 문은 무슨 열쇠로 열어? → **파란 열쇠**

**정보 없음**
> 관리인: 빨간 문은 파란 열쇠야.
> 안내판: 파란 문은 초록 열쇠로 열린다.
> 질문: 초록 문은 무슨 열쇠로 열어? → **모름**

**출처 충돌**
> 지나가던 사람: 초록 문은 빨간 열쇠로 열린대요.
> 관리인: 초록 문은 파란 열쇠로 열려.
> 질문: 초록 문은 무슨 열쇠로 열어? → **파란 열쇠**

**정정과 출처의 조합**
> 관리인: 파란 문은 초록 열쇠야.
> 지나가던 사람: 아니에요, 파란 문은 빨간 열쇠예요.
> 질문: 파란 문은 무슨 열쇠로 열어? → **초록 열쇠** (덜 믿을 만한 출처의 "정정"은 관리인 말을 덮지 못한다)

### 주 점수: 보정된 정답 점수

| 결과 | 점수 |
|---|---:|

### 함께 보고할 지표

- **능력별 정확도**: 정정, 방해, 소거, 정보 없음, 출처 충돌, 그리고 각 조합
- **보류 품질**: 잘못된 `모름` 비율, 답이 없을 때 찍은 비율
- **알아듣기 격차**: 정답 구조 조건 점수에서 실제 파서 조건 점수를 뺀 값
- **비용**: 모델 호출 수, 질문 수, p50/p95 지연, 최대 VRAM, 생성 토큰 수
- **학습 곡선 (Phase 4)**: 에피소드 순서에 따른 점수와 질문 수 변화

seed 6개(42–47)의 평균과 표준편차, 그리고 짝 비교 차이를 기록한다. 한 seed 결과만으로 우열을 정하지 않는다.

## 분할: 무엇을 처음 보게 할 것인가

하나의 분할에서 한 축만 숨겨서 무엇이 일반화 실패의 원인인지 구분한다.

| 분할 이름 | 시험에서 처음 보는 것 | 검사하는 능력 |
|---|---|---|
| `iid` | 없음 (새 에피소드만) | 기본 성능 |
| `phrasing` | 문장 표현 템플릿 | 알아듣기 일반화 |
| `composition` | 사례 유형 조합 (예: 정정 + 출처 충돌 + 소거) | 판단 조합 일반화 |
| `entity` | 새 문·열쇠 이름 | 이름에 기대지 않는지 |

각 분할에는 훈련, 검증, 시험 세트가 있다. 검증셋은 시험셋과 같은 축으로 처음 보는 것을 담되, 시험셋과는 겹치지 않게 만든다.

### 지름길 막기: 생성 단계 필터

먼저 에피소드의 계획을 정한다. 계획은 사례 종류, 출처 패턴, 질문할 문, 정답이다. 그다음 문장 표현, 방해 문장, 순서를 뽑는다. 이렇게 만든 후보가 사례 종류별 지름길 적중률을 찍기(1/3)에서 더 멀어지게 만들면, 계획은 그대로 두고 문장 쪽만 다시 뽑는다(adversarial filtering). 계획을 먼저 고정하기 때문에 필터가 사례 비율이나 정답 비율을 바꾸지 못한다.

구현하면서 실제로 확인한 함정이 두 가지 있었다.

- 계획까지 다시 뽑았더니 `모름` 문제만 남았다. 데이터의 85–97%가 `모름`이 됐는데도 검사는 통과했다. 그래서 사례 비율 검사를 추가했다.
- 전체 기준으로만 필터하니 사례 종류별 누수가 서로 상쇄됐다. 소거 문제에서 "가장 적게 나온 열쇠"가 63%, 단순 문제에서 "가장 많이 나온 열쇠"가 50%였는데 전체는 33%로 보였다. 그래서 필터와 검사를 사례 종류별로 적용한다.

### 지름길 검사 (분할마다 자동 실행)

다음 기준선을 훈련셋에 맞추고 시험셋에서 잰다. 허용 범위는 찍기 수준 ± max(3%p, 표준오차 3배)다. 하나라도 범위를 벗어나면 그 분할을 기각한다. 너무 낮은 경우도 기각한다(003–005의 3–11%처럼). 사례 종류별로도 같은 검사를 한다.

- 질문한 문의 이름만 보고 답하기
- 처음 언급된 열쇠, 마지막에 언급된 열쇠, 가장 많이 언급된 열쇠
- 마지막 발화의 열쇠
- 에피소드 길이와 출처 구성만 보고 `모름` 여부 맞히기
- 가장 많은 정답 하나만 계속 고르기

또한 다음 두 가지를 확인한다.

- 열쇠 정답 3종이 고르게 나오는지
- 사례 종류 비율이 설계 비율(`CASE_WEIGHTS`)과 맞는지. `모름` 비율은 약 20%다.

## 비교할 후보 구조

| 이름 | 구성 | 역할 |
|---|---|---|
| S0 지름길 기준선 | 위의 단순 규칙들 | 점수판이 공정한지 확인 |
| S1 정답 해결기 | 정답 구조를 받아 공리·출처·정정을 정확히 계산 | 상한선, 세계 자체 오류 검사 |
| L1 LLM 단독 | LFM2.5-1.2B에 세계 규칙과 발화를 프롬프트로 주고 답 받기 | 네 아이디어의 기준선 |
| P1 고정 파이프라인 | 파서(GLiNER 또는 규칙 파서) → 구조화 기억(코드) → 판단 규칙 → 답 | 전문 부품 조합의 첫 버전 |
| P1-gold | P1에 파서 대신 `gold_events` 입력 | 파싱 오류의 영향 분리 |
| P2 이후 | P1의 약한 칸을 학습 모델로 교체 (예: 출처 신뢰도 학습, 질문 정책) | 구조 탐색 |

S1과 P1-gold의 점수는 거의 같아야 한다. 다르면 판단 코드에 버그가 있는 것이다. L1과 P1을 같은 seed와 시험셋으로 짝 비교하는 것이 v1의 첫 번째 질문이다.

## v1 첫 질문

**같은 로컬 예산에서, 전문 부품 조합(P1)이 작은 LLM 단독(L1)보다 보정된 정답 점수가 높은가? 차이가 난다면 어느 능력에서 나는가?**

- P1이 이기면, 어느 능력에서 이겼는지가 다음 구조 실험의 출발점이 된다.
- L1이 이기면, 어느 부품이 병목인지(알아듣기 격차, 판단 규칙)를 P1-gold와 비교해 찾는다.
- 어느 쪽이든 유효한 결과다.

## 구현 순서

1. **생성기 — 완료**: Phase 1의 7개 사례 종류(`simple`, `self_correction`, `elimination`, `none`, `one_negative`, `conflict`, `conflict_correction`)와 표현 템플릿으로 에피소드를 결정적으로 생성한다 (`src/cognitive_lab/world/`).
2. **정답 해결기 S1과 생성기 자기 검사 — 완료**: 모든 에피소드에서 `answer`와 S1의 답이 같지 않으면 생성이 실패한다.
3. **분할과 지름길 검사 — 완료**: 네 분할 모두 seed 42에서 통과했다.
4. **점수판 CLI — 완료**: 에이전트는 `episode → answer` 함수 하나로 붙인다. 현재 등록된 에이전트는 S1과 참고용 `naive_reader`다. `naive_reader`는 질문한 문에 대해 마지막으로 나온 긍정 문장의 열쇠를 답한다.
5. **L1, P1, P1-gold 실행**: seed 42–47, 결과는 `artifacts/results/world-v1_*`에 저장한다.
6. 결과를 보고 Phase 2(질문하기)로 넘어갈지 정한다.

### seed 42 기준 참고 점수 (iid 시험셋)

| 에이전트 | 보정 점수 | 정확도 | 비고 |
|---|---:|---:|---|
| S1 정답 해결기 (= P1-gold) | 1.000 | 100% | 상한선 |
| P1-rule | 0.888 | 94.4% | 규칙 파서 + S1 판단 |
| naive_reader | 0.496 | 66.3% | 단순·정정·모름은 맞힘, 소거 0%, 출처 충돌 약 50% |

`naive_reader`처럼 문장을 읽기만 하는 방식은 절반 정도 점수를 받는다. 출처 판단과 소거 추론을 해야 나머지 점수를 얻을 수 있다.

### 첫 L1 실행에서 고친 점 (2026-10-06)

LFM2.5-1.2B를 지시만 주고 바로 풀게 했더니(zero-shot) 정확도가 31–32%였다. 점수는 −0.16(`choice`)과 −0.20(`generate`)으로 찍기 수준이었다. 답의 약 절반이 첫 보기인 "빨간 열쇠"였고, 질문한 문과 같은 색 열쇠를 고르는 경향도 있었다. 두 버릇을 측정에서 떼어내기 위해 다음을 바꿨다.

- 열쇠 이름을 색이 아닌 명사로 바꿨다. 기본 세트는 해·달·별, 검증용은 구름·바람·번개, 시험용은 꽃·돌·나무다.
- 보기 순서를 에피소드마다 섞고, 고른 보기의 위치 분포를 기록한다.
- 훈련셋 예시를 프롬프트에 넣는 few-shot 옵션(`--shots`)을 추가했다. 사례 종류마다 하나씩 고른다.
- 모든 결과 파일에 문제별 예측을 저장한다.

위 수정 뒤에도 프롬프트만 바꾼 L1은 찍기 수준이었다. seed 42 iid 기준 정확도는 27%였고, 예시 7개를 넣어도 같았다. 예시를 넣으니 첫 보기를 고르는 비율은 70%에서 51%로 줄었지만, 줄어든 만큼은 `모름`으로 옮겨갔다.

### 생성기 정합성 수정 (2026-10-06)

- 이전 버전에서는 다른 문에 대한 방해 문장에서, 같은 사람이 정정 표시 없이 말을 뒤집는 경우가 있었다. 이제 다른 문마다 숨은 진짜 열쇠를 정하고, 방해 문장은 그 진짜 열쇠와 일치하게 만든다. 정정 쌍(틀린 말 → 정정)은 그 문에 대해 다른 말을 하지 않은 사람만 쓴다.
- 사례 종류는 비율대로 섞은 묶음에서, (질문한 문, 정답) 9가지 조합은 섞은 묶음에서 뽑는다. 그래서 작은 검증셋에서도 비율이 우연히 쏠리지 않는다. 바꾼 뒤 seed 42–47 모두 지름길 검사를 통과했다.
- 이 수정 전에 측정한 L1 결과는 이전 데이터 기준이다.

### L1-LoRA: 같은 훈련 데이터로 미세조정한 LLM

`world/finetune.py`는 분할의 훈련 에피소드로 LFM2.5-1.2B에 LoRA를 학습한다. 설정은 rank 8, 학습 파라미터 약 555만 개다. 프롬프트는 zero-shot과 같고, 손실은 답 토큰에만 건다. 에폭마다 검증셋 300개의 보정 점수로 가장 좋은 어댑터를 고른다. 시험셋은 학습과 선택에 쓰지 않는다. 이것이 "같은 데이터를 받은 LLM 하나"라는 공정한 비교 대상이다.

### 결과: L1-LoRA 대 P1-rule (seed 42, 시험셋, 보정 점수)

| 분할 (시험에서 처음 보는 것) | L1-LoRA | P1-rule | 이긴 쪽 |
|---|---:|---:|---|
| iid (없음) | 0.952 | 0.878 | LoRA (단, 아래 주의 참고) |
| phrasing (말투) | **0.819** | 0.500 | LoRA |
| composition (사례 × 출처 조합) | 0.638 | **0.896** | P1 |
| entity (문·열쇠 이름) | 0.767 | **0.884** | P1 |

- **phrasing**: P1-rule은 처음 보는 부정 표현("~아닙니다")을 긍정으로 읽어서 소거와 부정 사례가 0%가 됐다. LoRA는 처음 보는 말투도 대부분 이해했다. 소거 사례는 58%였다.
- **composition**: LoRA는 규칙이 아니라 출처별 패턴을 배웠다. 훈련에서 "부정 하나뿐" 사례는 안내판이 말한 경우만 봤기 때문에, 관리인이 말한 같은 사례에서 87%를 찍었다. 그래서 `모름`이 정답인 문제에서 찍은 비율이 43.5%다. 같은 이유로, 지나가던 사람의 자기 정정만 본 상태에서 안내판의 자기 정정은 47%였다. P1의 판단 코드는 출처와 무관하게 같은 규칙을 적용한다.
- **entity**: 처음 보는 이름(꽃·돌·나무 열쇠)에서 LoRA는 보기에 없는 답을 12번 냈고, 소거 사례는 47%였다.
- **주의**: P1-rule의 부정 표지는 phrasing 훈련 템플릿에서만 뽑았다. 그래서 iid·composition·entity에서는 P1이 실제보다 불리하게 측정됐다. 이 세 분할에서 P1의 오류는 대부분 같은 템플릿(negate.05) 하나에서 나왔다.
- 검증 점수로 고른 에폭: iid와 composition은 2, phrasing과 entity는 1이었다(2에폭에서 검증 점수가 떨어짐). 아직 seed 1개 결과다.

**해석**: 학습된 모델은 **처음 보는 말투**에 강하고, 코드로 된 판단은 **처음 보는 조합과 이름**에 강했다. 이것은 "알아듣기는 학습 모델이, 판단은 구조화된 기억과 규칙이" 맡는 혼합 구조를 시험할 근거다. 다음 후보는 P2다. 같은 LFM과 같은 LoRA, 같은 데이터를 쓰되, 정답 대신 **문장별 사실 구조**(문, 열쇠, 긍정/부정)를 출력하도록 학습한다. 그 출력은 S1 판단기로 넘긴다. 모델과 데이터가 같으므로 차이는 "끝까지 한 번에 답하기"와 "읽기는 학습, 판단은 코드"의 구조 차이로만 생긴다.

### P2 구현: 부품과 연결

| 부품 | 방식 | 구현 |
|---|---|---|
| 언어 해석 (문장 → 사실) | 학습: LFM2.5-1.2B + LoRA (L1-LoRA와 같은 설정) | `world/parser_llm.py` |
| 공통 형식 | 설계: 문장마다 `문, 열쇠, 긍정/부정` 또는 `없음`, 그리고 확신도(greedy 출력의 확률) | 같은 파일 |
| 출처 | 그대로 전달. "[관리인]"은 메타데이터라서 언어 부품을 거치지 않는다 | 같은 파일 |
| 질문한 문 | 주어진 문 이름과 문자열로 맞춘다 | 같은 파일 |
| 기억 + 판단 | 코드: S1 해결기 | `world/solver.py` |
| 연결 정책 | 학습: 검증셋 점수가 가장 높은 확신도 기준값을 고른다. 에피소드 안 어느 문장이라도 확신도가 기준값보다 낮으면 `모름`으로 답한다 | `p2-lora-abstain` |

학습 데이터는 훈련셋에 있는 서로 다른 (이름 목록, 문장) 쌍이고, 정답 구조에서 라벨을 만든다. 언어 부품의 체크포인트는 검증셋 문장의 정확 일치율로 고른다.

**데이터 분석에서 확인한 점**: 이 세계는 문장 종류가 적다. iid와 composition은 훈련·시험 문장이 둘 다 같은 224종이다. 따라서 L1-LoRA가 composition에서 무너진 원인은 알아듣기가 아니라 판단이다. phrasing은 처음 보는 37종, entity는 처음 보는 이름을 쓴 224종이 시험에 나온다. 언어 부품의 일반화가 실제로 시험되는 곳은 이 두 분할이다. entity 훈련 데이터에는 문 이름 3개와 열쇠 이름 3개만 있어서, 언어 부품이 이름을 외울 위험이 있다. 그렇게 되면 다음 개선 후보는 학습할 때 이름을 무작위로 바꿔 넣는 데이터 증강이다.

### P2-nli: 언어 부품만 작은 전문 모델로 교체

`world/nli_parser.py`는 언어 부품을 mDeBERTa-v3-base-mnli-xnli(2.79억, NLI 전용)로 바꾼 버전이다. 공통 형식, 판단기, 보류 규칙은 P2와 같은 코드를 그대로 쓴다. 이것은 "부품 갈아끼우기" 시험이기도 하다.

- 읽는 방식: 문장 하나마다 "X 문은 Y 열쇠로 열린다" 가설 9개를 NLI로 판정한다. 뒷받침이 0.5 이상인 쌍이 있으면 긍정, 아니면 반박이 0.5 이상인 쌍이 있으면 부정, 둘 다 없으면 `없음`으로 읽는다.
- 미세조정 라벨은 세계 공리를 따른다. 긍정 사실은 그 쌍을 뒷받침하고, 같은 문의 다른 열쇠는 반박한다. 부정 사실은 그 쌍만 반박한다. 나머지는 무관이다.
- 단어 임베딩(전체 파라미터의 69%)은 고정한다. 처음 보는 이름의 사전학습 표현을 유지하려는 목적이다.
- 미세조정 전(`p2-nli-zeroshot`)과 후(`p2-nli`, `p2-nli-abstain`)를 모두 잰다. 이 모델의 NLI 학습 언어(XNLI 15개)에는 한국어가 없어서, 한국어는 언어 간 전이로만 다룬다.

### 결과: 구조 비교 (seed 42, 시험셋, 보정 점수)

| 방식 | 언어 해석 | 판단 | iid | phrasing | composition | entity |
|---|---|---|---:|---:|---:|---:|
| L1-LoRA | LFM 1.2B (단독) | LFM | 0.952 | 0.819 | 0.638 | 0.767 |
| P1-rule | 손으로 쓴 규칙 | S1 코드 | 0.878 | 0.500 | 0.896 | 0.884 |
| P2-nli (미세조정 전) | mDeBERTa 0.28B | S1 코드 | 0.349 | 0.213 | 0.432 | 0.787 |
| **P2** | LFM 1.2B + LoRA | S1 코드 | **1.000** | **1.000** | **1.000** | **1.000** |
| **P2-nli** | mDeBERTa 0.28B 미세조정 | S1 코드 | **1.000** | **1.000** | **1.000** | **1.000** |

- 두 P2 모두 네 분할에서 1000문제를 전부 맞혔다. 처음 보는 말투 37종과 처음 보는 이름이 든 문장 224종도 모두 정확히 읽었다. 무효 응답은 0이었고, 검증셋에서 고른 보류 기준값은 0이었다. 보류가 필요 없었다는 뜻이다.
- 정답 누출이 없는지 확인했다. 정답 구조는 훈련·검증 문장의 라벨을 만들 때만 쓴다. 시험에서 언어 부품이 받는 것은 문장, 이름 목록, 질문뿐이다.
- 같은 LFM과 같은 데이터를 써도 "끝까지 한 번에 답하기"(L1-LoRA)는 0.64–0.95, "읽기는 학습, 판단은 코드"(P2)는 1.00이었다.
- 부품 교체: 언어 부품만 LFM 1.2B에서 mDeBERTa 0.28B로 바꿔도 결과가 같았다. 판단 코드는 고치지 않았다. 학습 시간은 분할당 37–85초로 LFM(177–747초)의 약 1/9이었다. 추론 VRAM은 1.4GB로 LFM의 2.3GB보다 적었다.

**한계**: 이 세계 v1은 이제 변별력이 없다. 문장이 224종뿐이어서, 읽기만 맞으면 판단은 사람이 써 준 정확한 규칙(S1)이 해결한다. 이 결과는 "판단 규칙을 알고 있을 때, 읽기와 판단을 나누는 것이 낫다"는 것까지만 보여 준다. 시스템이 판단 규칙 자체를 **배워야** 하는 상황은 아직 시험하지 않았다. 그 부분이 다음 세계(v2)의 과제다.

### P1-rule (사람이 쓴 규칙 파서 + S1 판단), seed 42 시험셋

| 분할 | 보정 점수 | 정확도 |
|---|---:|---:|
| iid | 0.888 | 94.4% |
| phrasing | 0.472 | 73.6% |
| composition | 0.900 | 95.0% |
| entity | 0.910 | 95.5% |

부정 표지는 phrasing 분할의 훈련 템플릿에서만 뽑았다. 그래서 처음 보는 표현 "~열쇠가 아닙니다"(negate.05)는 전부 긍정으로 잘못 읽는다. 오류는 이 템플릿에서만 났다. phrasing 시험셋에는 부정 템플릿이 이것 하나뿐이어서, 소거와 부정 사례가 모두 무너졌다. 손으로 쓴 규칙은 본 표현에선 강하고, 처음 보는 표현에선 깨진다는 것이 숫자로 확인됐다. 학습된 파서(P1-nli 등)는 이 지점을 개선하는지로 평가한다.

### 실행 (프로젝트 루트, venv 활성화 상태)

```cmd
python -m cognitive_lab.world generate --seed 42
python -m cognitive_lab.world audit --seed 42
python -m cognitive_lab.world score --agent s1 --split iid --seed 42
```

L1(LFM2.5-1.2B 단독)은 `transformers`가 필요하다(`pip install -e .[llm]`). 두 방식으로 잰다.

- `l1-choice`: 보기 4개 각각을 답으로 썼을 때의 확률을 비교해 가장 높은 걸 고른다. 형식 오류가 없다.
- `l1-generate`: greedy 생성 결과에서 보기를 찾는다. 보기가 없는 응답은 무효로 처리하고 오답으로 센다.

L1은 정답 구조를 받지 않고, 세계 규칙과 문장과 질문만 받는다.

```cmd
python -m cognitive_lab.world score --agent l1-choice --split iid --seed 42 --device cuda
python -m cognitive_lab.world score --agent l1-generate --split iid --seed 42 --device cuda
```

데이터는 `artifacts/world-v1/data/{split}/seed-{seed}/`, 검사와 점수 결과는 `artifacts/results/world-v1_*.json`에 저장된다. Windows 콘솔에서 한글 출력이 깨지면 `set PYTHONIOENCODING=utf-8`을 먼저 실행한다.
