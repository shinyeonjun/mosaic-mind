## 한 문장 목표

처음 보는 규칙 과제에서 답부터 찍지 않고, **무엇을 시험하면 가설을 가장 잘 가를지 고른 뒤**, 관찰한 결과로 규칙을 추론해 새 사례를 푼다. 같은 규칙을 다시 만나면 기억을 재사용하고, 틀렸다는 근거가 생기면 기억의 적용 범위를 고친다.

## 지금까지 한 것과 아직 안 한 것

실험 001–005는 합성된 관찰 시퀀스를 보고 정답 키나 `ABSTAIN`을 고르는 GRU와 RIMs 계열 코어를 비교했다. 실험 003–005는 학습에서 빠진 규칙 조합까지 평가 범위를 넓혔다. 이 결과는 현재 과제에서 표현 구조와 규칙 조합 일반화를 비교하는 기준선이다.

하지만 이 모델들은 답을 고르기 전에 환경에 질문하거나 실험하지 않는다. 규칙을 여러 과제에 걸쳐 지속적으로 기억하거나, 새 반례로 낡은 기억을 고치는 능력도 아직 시험하지 않았다. 그러므로 지금 결과만으로 “처음 보는 문제를 스스로 탐구한다”고 말할 수는 없다.

## 실험 006: 질문을 고르면 실제로 더 잘 배우는가?

### 작은 세계

- 기존 합성 과제와 같은 3개 문, 3개 열쇠, 관련/방해 관찰을 쓴다.
- 각 세션에는 숨겨진 규칙 하나가 있다. 에이전트에게 규칙 ID는 주지 않는다.
- 규칙은 두 요소의 조합으로 만든다.
  - 적용 범위: 지정된 문만 보기 / 모든 문 보기
  - 열쇠 충돌 처리: 처음 나온 열쇠 / 마지막 열쇠 / 고정 우선순위 `RED < BLUE < GREEN`
- 따라서 숨은 규칙 조합은 총 6개다. 적용할 관찰이 없으면 정답은 `ABSTAIN`이다.
- 질문 하나는 순서가 있는 3개 이벤트다. 이벤트는 `(목표 문 여부, 열쇠 종류)`이고, 가능한 이벤트 6종을 3칸에 배치해 **216개 질문 후보**를 만든다. 숨은 규칙을 보지 않고 같은 후보 목록을 모든 정책에 준다.
- 환경은 선택한 질문 사례에 대한 정답 행동을 돌려준다. 에이전트는 최대 3번 질문한 뒤, 질문 목록에 없던 별도 사례를 풀거나 `ABSTAIN`한다.
- 반복 과제에서의 기억 효과를 보려면 한 세션 안에서 규칙은 유지한다. 규칙 변경과 교정은 다음 단계에서 별도로 시험한다.

규칙 조합 자체가 테스트에 새도록 무작위 행 분할을 하지 않는다. 세 폴드에서 6개 조합을 각각 한 번씩 테스트로 남기고, 테스트 조합은 그 폴드의 학습 데이터에서 제외한다. 각 조합은 학습·검증 안에서 사례를 분리한다. 결과는 기존 실험처럼 seed 42–47의 짝 비교로 기록한다.

### 비교군

1. 질문 없이 바로 답하는 정책
2. 무작위 질문
3. 미리 정한 순서대로 묻는 정책
4. 남은 가설을 가장 잘 구분하는 질문을 고르는 정보이득 기준선
5. 같은 관찰·질문 예산으로 학습한 GRU 256, 파라미터 수를 맞춘 GRU 205, RIMs

정보이득 기준선은 작은 가설 집합을 아는 알고리즘 기준선이지, 현실의 모든 규칙을 아는 범용 해결책이 아니다. 학습 코어가 이를 이기는지뿐 아니라, 그 차이가 제한된 질문 수에서도 유지되는지 본다.

첫 학습 버전(006A)은 정보이득 기준선이 고른 질문을 정답 행동으로 삼는 **행동 모방**이다. 이로써 GRU/RIMs가 상호작용 이력을 이용해 질문 정책을 재현하고, 학습에서 제외한 숨은 규칙 사례로 전이하는지 확인한다. 이는 보상만으로 탐구 행동을 스스로 발견하는 강화학습 실험은 아니다. 그 주장은 후속 006B에서 별도로 시험한다. 최종 답은 모든 비교군이 같은 명시적 후보 규칙 다수결을 사용해 질문 선택 효과만 분리한다.

006B는 정보이득 교사와 행동 라벨을 제거하고, 매 에피소드의 질문을 정책에서 표본 추출한다. 정책은 매 단계에서 미질문 후보 중 하나 또는 `STOP`을 고른다. 에이전트는 최대 3회 질문 후 별도 사례에 답하고, 보상은 `정답이면 1, 오답이면 0 - 실제 질문 수 × 0.05`다. REINFORCE가 이 최종 보상만으로 정책을 갱신한다. 검증은 질문 예산별 정답률이 아니라 예산 1–3의 평균 과제 보상으로 수행한다. 006A와 동일하게 후보 6개의 정확한 사후 필터링은 환경 인터페이스로 제공되므로, 이 실험은 **질문 정책의 보상 기반 학습**을 시험하며 규칙 추론이나 후보 목록 밖의 규칙 발견을 시험하지 않는다.

### 가설

**주 가설 H1 (006A 범위):** 정보이득 질문으로 학습한 제어기는 같은 질문 예산의 무작위·고정 순서 정책보다, 학습에서 숨긴 규칙 조합의 새 사례를 더 정확히 푼다. 지지되더라도 이는 규칙을 스스로 발견했다는 증거가 아니라, 교사 정책을 숨은 규칙 사례에 전이했다는 증거다.

**보조 가설 H2:** 같은 규칙을 다시 만났을 때 세션 기억을 쓰면, 정확도를 떨어뜨리지 않고 필요한 질문 수가 줄어든다. 이 가설은 반복 과제 결과로만 판단하고, 규칙 변경에 대한 기억 수정은 후속 실험으로 둔다.

GRU 대 RIMs 차이는 이번에도 비교하지만 어느 쪽이 이겨야 한다고 전제하지 않는다. 핵심 질문은 특정 신경망의 승리가 아니라 질문 선택과 기억 재사용의 효과다.

### 측정값과 판정

- **주요 지표:** 질문 예산 0·1·2·3회별 미관측 사례 정답률. 예산이 늘어날 때의 정확도 곡선과 곡선 아래 면적을 함께 보고한다.
- **보조 지표:** 평균 질문 수, 불필요한 질문 비율, 적용할 관찰이 없는 사례에서의 `ABSTAIN` 정확도.
- **기억 지표:** 반복 사례에서 줄어든 질문 수와 유지된 정확도. 규칙 교정 실험을 시작하면 교정 뒤 이전 규칙을 계속 적용한 비율도 추가한다.
- 결과는 폴드·seed별 짝 차이와 신뢰구간을 함께 적는다. 폴드를 서로 다른 현실 도메인 표본인 것처럼 취급하지 않는다.

H1은 미관측 규칙 조합에서 질문 예산별 정답률이 무작위·고정 정책보다 높을 때 지지된다. 질문을 더 많이 썼는데 점수만 오른 경우는 “효율적인 탐구”의 증거로 보지 않는다. 차이가 없거나 기준선보다 나빠도 유효한 결과다.

## 구현 순서

1. **환경 계약 고정 — 완료:** 숨은 규칙, 216개 질문, 질문 피드백, 4–8개 이벤트의 별도 답변 사례를 고정했다.
2. **환경과 기준선 — 완료:** 시뮬레이터와 무질문·무작위·고정·정보이득 정책을 구현했다. 동일 시드로 재현할 수 있다.
3. **006A 학습 코어 비교 — 완료:** GRU 256, 파라미터 수를 맞춘 GRU 205, RIMs를 정보이득 교사로 학습하고 3개 폴드·6개 seed에서 평가했다.
4. **006B 보상 기반 질문 정책 — 코드 구현:** 같은 세 코어를 정답 보상과 질문 비용만으로 REINFORCE 학습한다. 정보이득 행동 라벨은 만들지 않는다. `STOP` 행동으로 에이전트가 질문을 일찍 끝낼 수도 있다. 이 단계는 알려진 6개 규칙 후보 안에서 교사 없이 질문 정책을 배울 수 있는지 본다.
5. **알려진 부품의 새 조합 — 실험 007:** 18개 규칙을 `범위 × 처리 방식`으로 만들고, 각 폴드에서 조합 6개를 학습에서 뺀다. 모든 기본 부품은 학습에 남긴다. 테스트 때는 전체 18개 후보와 정확한 후보 필터를 제공하므로, 이것은 고정 문법 안의 조합 전이 실험이다. [실험 명세](experiment-007-compositional-rule-generalization.md)
6. **후보 목록 밖 규칙 일반화:** 007 이후 후보 카탈로그와 정확한 사후 필터에 의존하지 않고, 에이전트가 새 규칙을 표현·추가·검증할 수 있는지 별도로 시험한다.
7. **세션 기억·자연어 입력:** 반복 규칙에서 기억 on/off를 비교한 뒤 입력 해석 부품을 연결한다. 입력 해석과 탐구 제어 성능은 따로 평가한다.

코드는 기존 패키지의 독립 하위 모듈(예: `src/cognitive_lab/active/`)로 두고, 실험 명세는 이 문서와 별도 결과 JSON으로 관리한다. Jupyter는 결과 그래프나 일회성 확인에만 쓰고, 재현 가능한 실행 경로는 기존처럼 `python -m ...` CLI로 둔다. 첫 실험에는 새 모델 다운로드나 추가 패키지를 전제로 하지 않는다.

현재 기준선을 CMD에서 실행하려면 저장소 루트와 가상환경 활성화 상태에서 다음을 실행한다.

```cmd
python -m cognitive_lab.active --episodes 512 --probe-budget 3 --seed 42
```

요약 결과는 `artifacts/results/experiment-006_active-probing_seed-42.json`에 저장된다. 이 단계는 비신경망 기준선만 계산하며 GPU 학습은 하지 않는다. 기준선은 6개 규칙 후보를 모두 아는 작은 세계에서 균형 사례를 평가한다.

006A는 폴드별로 숨은 규칙 2개를 테스트에 남기고, 나머지 4개에서 교사 행동을 학습한다. 폴드는 같은 충돌 해결 규칙의 두 범위(`target_only`, `all`)를 짝지어 테스트한다. 입력에는 6개 후보의 현재 생존 여부, 질문 이력, 피드백, 남은 예산만 들어간다. 최종 테스트 사례는 질문이 끝날 때까지 정책에 보이지 않는다. 학습·검증·테스트 에피소드 수와 점수는 실행 결과 JSON에 기록한다.

실험 006A를 CMD에서 한 폴드·seed로 실행한다.

```cmd
python -m cognitive_lab.active.train_controller --fold 0 --seed 42 --device cuda
```

결과는 `artifacts/results/experiment-006A_fold-0_seed-42.json`, 가중치는 `artifacts/checkpoints/`에 저장된다. 전체 비교는 CMD 프롬프트에서 seed 42–47과 fold 0–2를 반복 실행한다. 정보이득·무작위·고정 기준선과 GRU/RIMs는 같은 테스트 사례를 사용한다.

전체 18개 실행을 한 번에 돌리려면 CMD 프롬프트에서 다음을 실행한다.

```cmd
for /L %F in (0,1,2) do @for %S in (42,43,44,45,46,47) do @python -m cognitive_lab.active.train_controller --fold %F --seed %S --device cuda
```

006B는 먼저 한 실행을 확인한다.

```cmd
python -m cognitive_lab.active.train_controller_rl --fold 0 --seed 42 --device cuda
```

보상 설정은 기본 `--probe-cost 0.05`이며 실행 JSON에 기록된다. 한 실행이 괜찮으면 18개 전체를 CMD에서 돌린다.

```cmd
for /L %F in (0,1,2) do @for %S in (42,43,44,45,46,47) do @python -m cognitive_lab.active.train_controller_rl --fold %F --seed %S --device cuda
```

결과는 `artifacts/results/experiment-006B_fold-{fold}_seed-{seed}.json`, 가중치는 `artifacts/checkpoints/`에 저장된다. 006B도 알려진 후보 6개를 벗어난 규칙 발견의 증거로 해석하지 않는다.

## 범위와 새로움에 대한 정직한 표현

이번 설계는 알려진 active learning, 정보이득 기반 질문 선택, 기억을 가진 에이전트 연구와 겹칠 수 있다. 프로젝트 조사 문서에도 이런 선례들이 정리돼 있다. 따라서 이 설계나 모듈 조합이 “사람들이 처음 만든 구조”라고 주장하지 않는다. 그 주장을 하려면 관련 연구를 더 조사하고, 무엇이 기존 방식과 다른지 구현 단위로 비교해야 한다.

지금 검증하려는 것은 더 작고 정확하다. **정해진 작은 세계에서 학습된 제어기가 유익한 실험을 고르고, 관찰을 기억해 미관측 규칙 조합에 전이할 수 있는가?** 여기서 성공한 부분이 생기면 그때 더 열린 입력과 도구 검색으로 넓힌다.
