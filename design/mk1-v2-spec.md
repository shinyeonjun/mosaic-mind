# MK1 v2 명세: 실제 글에서 도는 위성 시스템 (2026-10-09)

방향: `design/direction-2026-10-09.md`. 이 문서는 엔지니어링 명세다. 데이터 구조, 모듈 인터페이스, 채택 규칙, 지표를 정한다.

## 1. 칠판 스키마 (타입이 있는 그래프)

```
Entity   { id, surface: str, type: PER|LOC|ORG|DATE|NUM|MISC, span: (doc_id, start, end) }
Claim    { id, subj: Entity.id, pred: str, obj: Entity.id | literal,
           source: doc_id | "memory" | "board", conf: float[0,1], polarity: +1|-1 }
Query    { id, text, target: (subj?, pred?, obj?)   # 빈칸이 답
           answer_type: Entity.type | BOOL | UNKNOWN }
Answer   { query_id, value | "모름", conf, support: [Claim.id] }
```

주소는 `Entity.id`(구조)이고, 내용은 `Claim.conf`와 임베딩(학습)이다. v1 원칙("주소는 구조로, 내용은 학습으로")을 실제 글로 옮긴 것이다.

## 2. 모듈 (함수 시그니처)

| 모듈 | 입력 → 출력 | 구현 | 비용 |
|---|---|---|---|
| parse | text → [Entity], [Claim], Query | Gemma 4 E2B (QAT Q4_0 GGUF, llama.cpp), JSON 스키마 강제 | 측정 예정 |
| ner | text → [Entity] | GLiNER | 측정 예정 |
| read | (Query, doc) → Answer 후보 + span 점수 | mDeBERTa QA (KLUE) | KorQuAD에서 초당 31문제 (fp32) |
| entail | (sentence, Claim) → p(지지), p(반박) | mDeBERTa NLI | 초당 약 600 (fp32) ~ 1,600쌍 (fp16) |
| embed | text → R^384 | multilingual-e5-small | 측정 예정 |
| trust | 출처별 Claim × 피드백 → 출처 신뢰도 | 세는 중재자 (Beta 사전분포, 학습 숫자 2개) | 무시 가능 |
| reason | Claim 그래프 + Query → Answer | 순환 추론기 (TRM식, 우리가 학습) | 만들 것 |
| route | 칠판 상태 → 호출할 모듈 집합 | 학습형 사령탑 | 무시 가능 |
| memory | 확인된 Claim 저장, Query → 기억 Claim | 키: (subj, pred) 임베딩 | 무시 가능 |
| speak | Answer + support → 문장 | Gemma 4 E2B | 측정 예정 |

LLM(Gemma)은 parse와 speak만 맡는다. 추론(reason), 판단(trust), 기억(memory)은 맡지 않는다.

## 3. 모듈 채택 규칙

모듈 m마다 **검증셋**(외부 시험셋 아님)에서 잰다.

```
ΔS(m)   = score(MK1) − score(MK1 − m)
cost(m) = (latency_ms, VRAM_MB)
채택 ⇔ ΔS(m)의 세션 단위 95% 구간 하한 > 0
      또는 (ΔS ≈ 0 이고, 같은 일을 하는 모듈보다 latency·VRAM이 확실히 작음)
```

예: GLiNER. 가설은 "parse(Gemma)의 Entity 재현율 < GLiNER 재현율이고, 그 차이가 충돌 찾기와 기억 검색 점수로 이어진다"이다. (a) Gemma 단독, (b) GLiNER 단독, (c) 합집합의 Entity 재현율, 시간, ΔS를 재서 결정한다.

## 4. 시스템 지표

| 지표 | 정의 |
|---|---|
| 정확도 | 맞음 / 전체 (외부 시험은 공식 지표도 함께) |
| 선택적 정확도 | 답한 것 중 맞음, 거절률 |
| 반사실 강건성 | 틀린 문서를 섞었을 때의 정확도 하락폭 |
| 깊이 일반화 | 학습 깊이 ≤ 3 → 시험 깊이 5 정확도 |
| 온라인 학습 기울기 | 시간 순서 흐름에서 구간별 점수의 기울기 (가중치 고정) |
| 엮기 기여분 | score(MK1) − score(같은 LLM 혼자), score(MK1) − score(같은 메모리 예산의 단일 모델) |
| 비용 | 문제당 지연(ms), 최대 VRAM(MB), 학습한 파라미터 수 |

## 5. 구현 순서

1. `mk1v2/board.py`: 스키마와 직렬화
2. `mk1v2/llm_service.py`: llama-server 실행, parse/speak (JSON 스키마 강제), 지연·VRAM 측정
3. ner / embed / entail 래퍼: 같은 인터페이스, 비용 측정
4. `mk1v2/ablate.py`: 검증셋에서 모듈별 ΔS
5. reason(추론기), 그다음 외부 시험(봉인 규칙)

## 6. RGB 판정 규칙 (2026-10-09 고정, 봉인 90%를 열기 전에 정함)

RGB의 공식 지표는 시험장마다 따로다(잡음 정확도, 거절률, 오류 감지율, 합치기 정확도). 그래서 "거절이 늘고 정확도가 줄었다" 같은 맞교환을 판정할 수 없다. 이 프로젝트의 채점 원칙(맞음 +1, 모름 0, 틀림 −1)으로 **하나의 순점수**를 정한다. 공식 지표도 함께 보고한다.

| 시험장 | 맞음 (+1) | 0 | 틀림 (−1) |
|---|---|---|---|
| 잡음 0 / 0.4 / 0.8, 합치기 | 답 포함 | 거절 | 그 밖 |
| 거절 (답이 문서에 없음) | 거절 | — | 답을 냄 |
| 거짓 문서 | 오류를 알리고 바른 답 | 오류만 알림, 또는 거절 | 거짓 답을 그대로 냄 |

- **주 지표**: 여섯 시험장 순점수의 평균(시험장마다 같은 무게).
- **판정**: MK1 − Gemma 4 E4B 혼자(같은 메모리 예산 상대), MK1 − Gemma 4 E2B 혼자(MK1 안의 LLM). 문제 단위로 짝지은 부트스트랩 95% 구간(RGB는 세션이 없으니 문제 단위가 맞다).
- 문턱값 같은 모든 조정은 개발용 10%에서만 한다. 봉인 90%는 시스템을 얼린 뒤 한 번만 연다.
- **현재 개발용 상태(기록)**: MK1 v2 첫 버전은 Gemma 혼자를 넘지 못했다. 원인은 영어 거절 판단과 지식 부족이다. 다음 작업은 거절 판단 위성(A)과 지식 위성(B)이다.

## 7. RGB 최종 판정 (2026-10-09, 봉인 90%를 한 번 엶)

시스템은 `db1446e`에서 얼렸다. 문턱값은 개발용 10%에서 정한 그대로다(읽기 위성의 답 없음 여유 ≥ 1.0일 때만 근거로 인정, NLI 뒷받침은 쓰지 않음). 첫 실행은 메모리 부족으로 Gemma E2B의 첫 시험장(잡음 0%)만 끝난 채 멈췄다. 사용자가 같은 얼린 시스템으로 처음부터 다시 돌렸다. 그 사이 MK1은 바뀌지 않았다.

`python -m cognitive_lab.mk1v2.rgb_compare --set final` → `artifacts/results/exam-rgb_verdict_final.json`

| 시험장 (순점수) | Gemma 4 E2B 혼자 | Gemma 4 E4B 혼자 | **MK1 v2** (E2B + 영어 읽기 위성 + 판단) |
|---|---:|---:|---:|
| 잡음 0% (270) | 0.963 | **0.993** | 0.956 |
| 잡음 40% (270) | 0.967 | **0.985** | 0.963 |
| 잡음 80% (270) | 0.863 | **0.893** | 0.789 |
| 거절 (270) | −0.185 (거절률 41%) | 0.170 (59%) | **0.563 (78%)** |
| 거짓 문서 (90) | −0.944 | −0.956 | −0.900 |
| 정보 합치기 (90) | 0.422 | **0.556** | 0.278 |
| **평균 (주 지표)** | 0.348 | 0.440 | **0.441** |

**판정 (미리 정한 규칙: 문제 단위 짝지은 부트스트랩 95% 구간)**
- **MK1 v2 − Gemma E2B 혼자(MK1 안의 LLM) = +0.094, 구간 (+0.066, +0.123)**. 엮는 층이 같은 LLM에 뚜렷한 값을 더한다.
- **MK1 v2 − Gemma E4B 혼자(같은 메모리 예산의 더 큰 단일 모델) = +0.001, 구간 (−0.036, +0.036)**. 통계적으로 **비긴다**. 더 작은 LLM(E2B)을 품고 더 큰 모델(E4B)과 같은 점수다. 이기지는 못했다.

**어디서 얻고 어디서 잃었나**
- 얻음: **거절**. 지어내던 답을 영어 읽기 위성이 막아서, 거절률이 41%에서 78%가 됐다(E4B는 59%).
- 잃음 1: **정보 합치기** 0.42 → 0.28. 답이 여러 문서에 흩어져 있으면 문서 하나하나의 근거 점수가 낮아서, 맞는 답까지 거절했다. 근거를 문서 하나가 아니라 **여러 문서를 합쳐서** 봐야 한다.
- 잃음 2: **잡음 80%** 0.86 → 0.79. 같은 이유로 일부 정답을 거절했다.
- 그대로: **거짓 문서**. 세 시스템 모두 전혀 감지하지 못한다. 지식 위성(B)이 필요하다.

**정직한 메모**
- 문턱 하나를 개발용 30문제에서 정했다. 봉인분에서도 거절 이득은 그대로 재현됐다(개발용 거절률 80% → 봉인 78%).
- 주 지표는 여섯 시험장을 같은 무게로 평균한다. 거절 시험장이 하나뿐이라, 거절에 강한 시스템이 유리하거나 불리하게 보이지는 않는다. 다만 다른 무게를 쓰면 결론이 바뀔 수 있다(예: 잡음 시험장만 보면 E4B가 앞선다).

**다음 개선 (새 시험으로 판정해야 함, RGB 봉인분은 이미 썼다)**
1. 근거를 여러 문서에서 합치기 (합치기·잡음 손실을 줄임)
2. 지식 위성 (거짓 문서)
3. 판단을 문턱 대신 학습된 작은 판정기로 (SQuAD 같은 외부 데이터로 학습)

## 8. 개선 1 시도: 근거 합치기와 여러 단계 추론 (2026-10-09, 개발용만, 봉인 안 엶)

**RGB 개발용: 두 읽기 통로의 합의를 근거로 쓰기** → 평균 0.511 → 0.522(30문제에서 잡음 수준). 채택하지 않았다. 답 없는 문제에서는 Gemma와 읽기 위성이 **같은 무관한 문서**를 읽고 같은 답을 낸다. 그래서 "합의"가 독립된 증거가 아니었다. **투표는 서로 다른 출처일 때만 근거가 된다.**

**새 외부 시험 MuSiQue-Full** (`mk1v2/musique.py`, 500쌍 중 개발용 50쌍 / 봉인 450쌍, CC BY 4.0)
| 개발용 (100문제) | Gemma E2B 혼자 | Gemma E4B 혼자 |
|---|---:|---:|
| 순점수 | 0.51 | 0.64 |
| 답 있는 문제 정답률 / 거절률 | 0.36 / 0.42 | 0.48 / 0.36 |
| 답 없는 문제 거절률 | 0.94 | 0.98 |

- RGB와 정반대다. 여러 단계 문제에서 Gemma는 지어내기보다 **포기**를 많이 한다. 거절을 더하는 판정기는 여기서 해가 된다.

**여러 단계 추론 파이프라인** (`mk1v2/multihop.py`): Gemma가 질문을 쪼개고, 영어 읽기 위성이 단계마다 답을 찾아 다음 질문에 넣는다. Gemma가 포기한 문제만 구해 낸다.
- 첫 실행은 **쪼개기가 한 번도 일어나지 않았다**. llama.cpp의 JSON 형식 강제 경로에서 Gemma 4가 꺼 둔 생각 모드로 돌아가 빈 답을 냈다(내 배선 버그). 줄 단위 출력으로 고쳤다.
- 고친 뒤에도 개발용 최선은 "끼어들지 않기"(0.50)다. 끼어들면 문턱에 따라 0.35–0.49다. 원인은 E2B가 쪼갠 질문의 품질이 낮고, 단계마다 오류가 쌓이는 것이다.
- 단서: 쪼개지 않고 읽기 위성이 원래 질문을 통째로 읽었을 때, Gemma가 포기한 답 있는 문제 23개 중 10개를 맞혔다. 동시에 답 없는 문제에도 확신 있게 답하는 경우가 있어서, 판정 문턱으로는 둘을 가르지 못했다.

**결론**: 실제 글의 여러 단계 추론("생각")이 지금 MK1의 가장 큰 빈칸이다. 작은 LLM에게 쪼개기를 맡기고 작은 읽기 위성으로 잇는 방식은 단일 LLM 안의 추론보다 약했다. MuSiQue 봉인분은 아직 열지 않았다(얼린 개선안이 없음).
