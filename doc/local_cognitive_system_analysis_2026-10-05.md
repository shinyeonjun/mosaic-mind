# 로컬 인지 시스템 구상: 근거와 1차 실험

조사일: 2026-10-05  
검토 문서: [`test.txt`](D:/AI_great/doc/test.txt), [`local_cognitive_system_research_2026-10-05.md`](D:/AI_great/doc/local_cognitive_system_research_2026-10-05.md)

두 문서는 모델 이름을 늘리기보다, 기억·상태·호출을 학습하는 작은 코어를 검증하자는 방향으로 수렴한다. 원 논문과 대조한 결론도 이 방향은 **실험할 가치가 있지만, 성능이 입증된 설계는 아직 아니다**이다. 특히 고정된 언어 모델 표현과 학습 가능한 작업망의 결합은 직접 선례가 있으나, 서로 다른 사전학습 모델 여러 개를 묶고 그 사용법을 학습하는 시스템은 그 선례와 구분해야 한다.

## 주장별 근거와 한계

### Riveland & Pouget: 가장 직접적인 선례

이 연구는 50개 심리물리 과제의 지시문을 사전학습 Transformer로 임베딩하고, 언어 모델 가중치는 고정한 채 학습된 선형 투영과 256개 은닉 유닛 GRU가 감각 입력에서 운동 출력을 내도록 학습했다. SBERT 임베딩을 쓴 모델은 학습에서 보지 않은 과제를 평균 79% 정확도로 수행했고, 더 큰 SBERT 모델은 83%를 기록했다. 과제 구조를 명시적으로 넣은 기준선은 88%였다. 이는 **고정된 사전학습 언어 표현 + 학습 가능한 과제 수행망**이 새로운 지시 조합으로 일반화할 수 있다는 직접 근거다. [Nature Neuroscience 논문](https://www.nature.com/articles/s41593-024-01607-5)

다만 이 논문은 서로 다른 언어 모델(GPT, BERT, SBERT, CLIP)을 각각 대체 표현기로 시험했을 뿐, 여러 외부 모델의 출력을 한 컨트롤러가 조정한 연구가 아니다. 제한된 영어 지시문과 통제된 감각운동 과제에서의 결과이므로, 한국어 대화 해석·장기 기억·도구 선택까지 증명하지 않는다. 따라서 아이디어의 타당성을 지지하지만 그대로의 시스템 성능을 보증하지는 않는다. [논문 본문과 방법](https://www.nature.com/articles/s41593-024-01607-5)

### RIMs와 shared workspace: 구조 후보이지, 완성된 모델 묶음이 아니다

RIMs는 하나의 순환 신경망 안에 별도 파라미터를 가진 메커니즘들을 학습한다. 입력에 따라 일부만 활성화·갱신하고, 나머지는 상태를 유지하며, 활성 모듈끼리 제한적으로 정보를 교환한다. 저자들은 시간 패턴·객체·환경 변화가 있는 과제에서 일반화 이점을 보고했다. 핵심은 전문 모듈의 존재 자체보다 **공동 학습된 선택적 갱신과 희소 통신**이다. [RIMs 논문](https://arxiv.org/html/1909.10893)

Shared Global Workspace 연구는 모듈이 용량 제한이 있는 공간에 정보를 쓰기 위해 경쟁하고, 그 내용이 다시 모듈들에 전달되는 구조를 구현했다. 이미지·물리·게임 계열의 실험에서 일부 기준선보다 나은 결과를 보고했고, workspace의 지속성 및 용량 제한을 제거한 비교도 수행했다. 따라서 workspace는 로그나 공용 JSON 저장소가 아니라 **이후 모듈 계산을 바꾸는 학습된 통신 경로**를 뜻한다. 이 연구 역시 모듈들이 함께 학습되는 신경망 실험이며, 임의의 동결 Hugging Face 모델들이 공유 메모리를 쓰면 같은 이득을 얻는다는 증거는 아니다. [ICLR 2022 논문](https://openreview.net/pdf?id=XzTtHjgPDsT)

### 도구 오케스트레이션과도 구분해야 한다

가까운 시스템 선례로 SayCan은 언어 모델이 높은 수준의 행동 후보를 제안하고, 학습된 affordance/value 점수가 실제 환경에서 가능한 행동인지 걸러낸다. Toolformer는 하나의 언어 모델이 API 호출 시점·인자·결과 사용을 학습한다. 둘 다 언어와 행동/도구를 연결하는 근거지만, 작은 순환 코어가 서로 다른 동결 전문 모델을 장기 기억과 함께 조정해 이득을 냈다는 증거는 아니다. 따라서 비교군은 고정 파이프라인에 더해 단일 모델의 도구 호출 방식도 둘 수 있다. [SayCan 논문](https://arxiv.org/abs/2204.01691) · [Toolformer 논문](https://arxiv.org/abs/2302.04761)

### 공개 모델 점수는 후보 선별에만 쓴다

Julia-1 원자료의 한국어 MASSIVE 성적은 2,974개 중 2,296개, 77.20%다. 모델 카드가 명시하듯 MASSIVE 평가는 18개 시나리오 라벨 분류이지, 슬롯 추출이나 일반 추론 점수는 아니다. 이 수치는 한국어 유한 선택 기준선을 세울 근거는 되지만, 기억 정책 모델로 평가할 근거는 아니다. [Julia-1 모델 카드](https://huggingface.co/SupersonicLabs/Julia-1) · [저자 공개 평가 원자료](https://huggingface.co/SupersonicLabs/Julia-1/blob/main/metrics/accuracy-20260924.json)

GLiNER2.5 다국어 카드에는 엔티티, 분류, 구조화 레코드, 관계 추출 기능과 287M 파라미터가 기재돼 있다. 다만 카드의 다국어 표기만으로 한국어의 부정, 행위 주체, 시간 변경, 사실 정정 성능까지 입증되지는 않는다. 후보 파서는 이런 한국어 최소쌍에서 직접 평가해야 한다. [GLiNER2.5 multilingual 모델 카드](https://huggingface.co/fastino/gliner2.5-multi-v1)

### HRM과 TRM: 퍼즐 전용 재귀 계산의 근거

HRM은 27M 파라미터의 재귀 모델로 Sudoku·미로·ARC 같은 구조화된 입력/출력 과제를 처음부터 학습했다. 자연어 모델이나 범용 텍스트 추론기로 배포할 근거는 없다. ARC 점수의 해석에는 추론 비용도 중요하다. 저자들은 각 시험 입력에서 1,000개의 증강 변형을 풀고 역변환한 뒤, 가장 흔한 답 두 개를 제출했다. 반면 해당 논문의 Sudoku·미로 평가는 단일 추론 패스였다. 따라서 “27M 모델”만으로 비용을 비교하지 말고 과제별 증강·재귀·시험 시 계산량을 함께 봐야 한다. [HRM 논문 v3, 평가 방법](https://arxiv.org/html/2506.21734v3)

TRM은 이 비교에 중요한 반례다. 저자는 더 단순한 2층 단일 재귀망으로 같은 퍼즐 계열에서 HRM보다 높은 점수를 보고했으며, ARC에서도 1,000개 증강 변형의 시험 시 예측을 모아 답을 정한다. 즉 HRM의 결과를 두 계층 구조나 뇌 비유만의 효과로 돌리기 어렵다. 이 결과는 사용자 시스템에 HRM/TRM 체크포인트를 붙이라는 뜻이 아니라, **단일 재귀망을 모듈형 코어의 필수 비교군으로 둘 이유**다. TRM은 arXiv 논문이며, 저자도 데이터셋에 따라 최선의 구조가 다르고 재귀가 왜 유효한지 설명이 남아 있다고 명시한다. [TRM 논문](https://arxiv.org/html/2510.04871)

## 동결 이종 모델 + 학습 가능한 코어: 합리적인 첫 실험인가?

**그렇다. 단, 검증할 주장을 좁혀야 한다.** 동결 입력 모델은 입력 해석기를 고정해 코어의 학습과 오류를 분리하기 좋고, Riveland & Pouget 연구는 그 구성의 일부를 직접 뒷받침한다. 그러나 여러 모델을 섞는 것 자체가 이득이라는 근거는 없다. 모델별 출력의 의미·오류·점수 척도가 다르므로, 임베딩을 무작정 이어 붙이거나 서로 다른 confidence 점수를 같은 확률처럼 취급하면 안 된다. 아래 제안은 선행연구의 직접 결과가 아니라 그 결과에서 도출한 실험 설계다.

1. 작은 시뮬레이터에서 먼저 검사한다. 한국어 지시로 규칙이 주어지고, 방해 정보와 정정이 들어오며, 제한된 행동으로 목표를 이루는 환경을 만든다. 코어의 출력은 `유지 / 기록·교체 / 검색 / 검증 / 행동 / 보류 / 종료`처럼 제한한다.
2. 파서와 검색기 등 입력 모듈은 우선 동결하고 출력을 고정된 타입의 레코드로 넘긴다. 원문 근거, 시점, 출처, 모델 식별자를 보존한다. 코어가 무엇을 기억하고 어떤 모듈을 부를지 학습한다.
3. 같은 모듈과 정보, 행동, 호출·연산 예산을 쓰는 **고정 규칙 파이프라인**, **작은 단일 GRU 코어**, 그리고 이후의 **RIMs/workspace 변형**을 비교한다. 모듈 추가가 성능을 높이는지도 하나씩 끄거나 정답 출력을 넣어 확인한다.
4. 두 조건을 나눈다. 정답으로 구조화된 관측을 입력해 코어 자체를 평가하고, 동결 한국어 파서 출력을 입력해 전체 파이프라인을 평가한다. 그래야 파싱 오류를 기억·제어 실패로 착각하지 않는다. 데이터는 문장 행 단위가 아니라 규칙 조합·가상 세계 단위로 분리한다.
5. 목표 달성률뿐 아니라 정정 후 오래된 사실을 버리는 정확도, 필요한 기억 보존율, 불필요한 호출 수, 보류 뒤 오류율, 지연을 기록한다. 모듈 수나 모델 크기만으로 승자를 정하지 않는다.

따라서 첫 연구 질문은 “여러 모델을 연결하면 똑똑해지는가?”가 아니라 **“같은 동결 부품과 계산 예산에서 학습된 상태·호출 정책이 규칙 기반 파이프라인이나 단일 GRU보다 정정·기억·조합 일반화를 개선하는가?”**가 적절하다. 먼저 단일 GRU가 이기면 그 구성이 기준선이고, RIMs/workspace는 필요한 경우에만 후속 비교로 추가하면 된다. 새로움은 모델 개수가 아니라 한국어 환경에서 이 차이를 재현 가능하게 보였는지에 달려 있다.

## 최종 권고

작은 환경과 고정된 모듈 출력으로 컨트롤러의 필요성을 먼저 시험한다. 입력 파서의 정답 조건과 실제 한국어 파서 조건을 분리하고, 정답 구조 입력에서도 코어가 이기지 못하면 언어 모델을 더 붙이지 않는다. RIMs/shared workspace는 확정 설계가 아닌 비교 후보로, HRM/TRM은 자연어 부품이 아닌 재귀 계산의 과제별 참고 구조로 취급한다.

모델 가중치 실행·속도 측정과 한국어 실측 성능은 이 검토에서 수행하지 않았다. 위 점수는 각 논문의 저자 보고치이며, 이 시스템에서의 성능을 뜻하지 않는다.
