조사해보니, **네가 만들려는 방향에는 근거가 있어. 다만 “좋은 로컬 모델 여러 개를 연결한다”에서 끝내면 부족하고, 그 모델들의 정보로 기억을 유지하고 다음 행동을 선택하는 작은 인지 코어를 따로 학습시키는 쪽이 더 맞아.**

그리고 앞서 내가 추천했던 구성은 수정해야 해. **`Reranker = 작업기억 제어`, `Reward model = 사실 검증`, `작은 LLM = 실행 통제`로 바로 대응시킨 건 부정확했어.** 이름이 비슷한 것과 실제로 그 기능을 학습한 것은 다르다.

이번에는 **36개 체크포인트와 22편의 논문·연구 자료**를 역할별로 정리했어. 모델 카드, 학습 목적, 공개 평가 원자료, 논문 초록과 접근 가능한 본문을 대조했다. 다만 **모델을 직접 실행해서 얻은 성능 순위는 아니다.** 아래의 채택·보류는 근거에 따른 **실험 우선순위**다.

전체 저장소와 논문 목록은 local_cognitive_system_research_2026-10-05.md[모델·논문 조사 노트](sandbox:/mnt/data/local_cognitive_system_research_2026-10-05.md)에 남겼고, 여기서는 설계를 바꾸는 중요한 발견부터 설명할게.

# 1. 가장 중요한 결론: ‘부품 모델’과 ‘인지 코어’를 분리해야 한다

내가 지금 권하는 구조는 다음과 같아.

> **입력을 이해하는 작은 모델들 + 기억을 찾는 모델 + 상태를 유지하고 연산을 선택하는 작은 순환 신경망 + 필요한 경우에만 후보를 만드는 생성 모델.**

여기서 핵심은 마지막 생성 모델이 아니라 **상태를 가진 제어 코어**야.

왜냐하면 다음 기능들은 서로 다르기 때문이야.

| 필요한 기능 | 기존 모델이 잘하는 것 | 그것만으로 해결되지 않는 것 |
|---|---|---|
| 입력 이해 | 엔티티 추출, 의도 분류, 문장 표현 | 부정·조건·시간·정정을 포함한 완전한 상황 해석 |
| 기억 검색 | 현재 질문과 비슷한 경험 찾기 | 지금은 관련 없어 보여도 나중에 필요한 정보 유지 |
| 근거 평가 | 문서 관련도, 주장의 근거 지지 여부 | 무엇을 더 조사하고 언제 결론을 내려야 하는지 |
| 후보 선택 | 제시된 선택지 중 하나 고르기 | 선택지에 없는 새로운 계획 구성 |
| 작업기억 제어 | 별도 정책을 학습하면 가능 | 일반적인 embedding·reranker가 기본 제공하는 기능은 아님 |
| 실행 통제 | 다음 연산·행동을 선택하는 정책 | 일반 응답 품질 reward를 그대로 사용해서는 안 됨 |

특히 PBWM은 **정보를 선택적으로 유지·갱신하는 메커니즘**을 모델링하고, Qwen reranker는 **질문과 문서의 관련도**를 점수화한다. 둘은 학습 대상부터 다르다. [PubMed](https://pubmed.ncbi.nlm.nih.gov/16378516/)

따라서 연구 질문도 이렇게 잡는 편이 좋다.

> “어떤 모델 다섯 개를 조합할까?”  
> 보다는  
> **“서로 다른 전문 모델의 결과를 이용해, 작은 신경망이 무엇을 기억하고 어떤 계산을 더 할지 학습할 수 있을까?”**

이쪽이 네가 말한 ‘여러 뇌의 오케스트레이션’에 더 가깝다.

# 2. 뇌과학에서 실제로 가져올 만한 원리

## 2-1. 가장 직접적으로 맞는 논문이 있었다

**Riveland & Pouget, 2024 — _Natural language instructions induce compositional generalization in networks of neurons_**

이번 조사에서 네 아이디어와 가장 직접적으로 닿는 논문 중 하나야.

이 연구는 **사전학습 언어 모델이 만든 지시문의 표현을, 별도로 학습한 과제 수행 신경망에 전달하는 구조**를 다룬다. 언어를 처리하는 부분과 실제 과제를 수행하는 부분을 구분하고, 새로운 지시·과제 조합에 대한 일반화를 조사했다. [Nature](https://www.nature.com/articles/s41593-024-01607-5)

우리 식으로 해석하면:

> 사용자 문장 → 지시의 표현 → 별도 인지·행동 신경망 → 행동 선택

이야.

**“대답을 잘 쓰는 모델이 곧 전체 지능일 필요는 없다”는 네 발상을 실제 계산 모델로 시험한 선례**라는 점에서 중요하다. 다만 연구 범위는 통제된 과제들이고, 이것이 곧 범용 대화 지능을 완성했다는 뜻은 아니다. [ResearchGate](https://www.researchgate.net/publication/379052030_Natural_language_instructions_induce_compositional_generalization_in_networks_of_neurons)

참고로 인간에서 언어와 다른 인지 기능의 구분을 검토한 Fedorenko 등의 2024년 논문도 관련이 있다. 하지만 여기서 **“인간에게 비언어적 사고가 존재한다”와 “LLM은 추론할 수 없다”는 별개의 주장**이야. 후자는 이 논문으로 증명되지 않는다. [Nature](https://www.nature.com/articles/s41586-024-07522-w)

## 2-2. 설계에 반영할 원리와, 과장하면 안 되는 부분

| 연구 축 | 실제로 가져올 원리 | 우리 시스템에서의 적용 제안 | 주의점 |
|---|---|---|---|
| **Global Latent Workspace** — VanRullen & Kanai, 2021 | 전문 시스템의 정보를 공통 표현으로 연결 | 모듈별 결과를 공유 상태로 변환하는 어댑터 | 완성된 범용 모델이 아니라 연구 로드맵이다. [arXiv](https://arxiv.org/abs/2012.10390) |
| **PBWM** — O’Reilly & Frank, 2006 | 작업기억을 선택적으로 유지·갱신 | `유지 / 기록 / 교체` 정책 학습 | 현재 관련도가 높다는 것과 앞으로 기억할 가치가 있다는 것은 다르다. [PubMed](https://pubmed.ncbi.nlm.nih.gov/16378516/) |
| **Complementary Learning Systems** — Kumaran 등, 2016 | 빠른 경험 학습과 장기적인 일반화의 상호작용 | 사건 저장소와 학습된 지식을 구분하고 검증된 경험을 재학습 | 단순히 ‘해마=DB, 피질=LLM’이라고 대응시키면 지나친 단순화다. [PubMed](https://pubmed.ncbi.nlm.nih.gov/27315762/) |

| **Prioritized Memory Access** — Mattar & Daw, 2018 | 기억 접근을 미래 의사결정의 개선과 연결 | 비슷한 기억보다 행동에 도움이 되는 기억을 우선 | 의미 유사도만으로 기억 접근을 설명할 수 없다. [Nature](https://www.nature.com/articles/s41593-018-0232-z) |

여기서 내 판단은 명확해.

**뇌 영역 이름을 가져오는 것보다, `유지`, `선택적 갱신`, `제한된 공유 공간`, `필요할 때만 연산`, `경험에 따른 정책 변화`를 구현하는 것이 중요하다.**

반대로, 서로 다른 모델의 의견이 충돌한다고 그것을 곧바로 predictive coding이라고 부르면 안 돼. 원래 모델은 **예측과 관측 사이의 오차**를 다룬다. 우리도 그 원리를 쓰려면 “이 행동을 하면 어떤 상태가 될 것인가”를 예측하고, 실제 결과와 비교해야 한다. [Nature](https://www.nature.com/articles/nn0199_79)

# 3. 실제 신경망 구조로는 무엇이 가까운가

뇌과학 논문만 읽으면 설계 비유에서 멈출 수 있어. 그래서 **실제로 학습되는 계산 구조**도 같이 봤다.

## 3-1. 가장 가까운 출발점: RIMs와 Shared Workspace

**Recurrent Independent Mechanisms, RIMs**는 작은 순환 모듈들을 두고, 입력에 따라 일부만 갱신하며 모듈 사이의 정보 교환을 제한하는 구조야. “여러 전문 모듈이 각자 상태를 유지하면서 필요한 순간에 협력한다”는 점에서 네 구상과 가깝다. [arXiv](https://arxiv.org/abs/1909.10893)

여기에 **_Coordination Among Neural Modules Through a Shared Global Workspace_**는 제한된 공유 메모리, 쓰기 경쟁, 정보 재전파를 실제 학습 가능한 구조로 넣는다. 단순히 결과를 한곳에 모으는 로그 저장소가 아니라, **공유 공간이 이후 모듈의 계산에 영향을 준다.** [arxiv.org](https://arxiv.org/html/2103.01197v2)

다만 중요한 차이가 있어.

> 이 연구들에서는 모듈과 통신 방식이 학습된다.  
> 임의의 Hugging Face 모델들을 연결했다고 같은 성질이 자동으로 생기는 것은 아니다.

그래서 내 추천은 **RIMs를 그대로 ‘범용 뇌’라고 쓰는 것이 아니라, 우리가 만드는 제어 코어의 비교 구조로 쓰는 것**이야.

## 3-2. HRM·TRM은 매력적이지만, 적용 범위를 잘 봐야 한다

| 구조 | 매력적인 점 | 이 프로젝트에서의 위치 |
|---|---|---|
| **RIMs** | 여러 작은 상태 보유 모듈, 선택적 업데이트 | 모듈식 인지 코어의 우선 연구 후보. 자체 과제로 학습해야 한다. [arXiv](https://arxiv.org/abs/1909.10893) |
| **DNC** | 외부 메모리 읽기·쓰기와 신경망 제어를 함께 학습 | 메모리 제어 실험의 선례. DB 연결만으로 구현되는 기능은 아니다. [Nature](https://www.nature.com/articles/nature20101) |
| **HRM** | 서로 다른 시간척도의 반복 계산, 약 27M 규모 | 격자·퍼즐 과제용 추론 구조의 비교군. 자연어 범용 추론 모델로 바로 사용할 수는 없다. [arXiv](https://arxiv.org/html/2506.21734v3) |
| **TRM** | 약 7M의 더 단순한 재귀 모델 | 여러 모듈이 정말 필요한지 검증할 강한 비교군. [arXiv](https://arxiv.org/html/2510.04871v1) |
| **DreamerV3** | 상태 전이 예측과 행동 가치 학습 | ‘행동 결과를 예상하는 모델’의 설계 참고. 공개 모델을 채팅용 세계 모델로 바로 전용하는 것은 별개 문제다. [Nature](https://www.nature.com/articles/s41586-025-08744-2) |

HRM은 특히 숫자만 보면 오해하기 쉬워. 논문의 ARC 평가에는 **테스트 입력당 1,000개 증강 변형을 풀고 투표하는 과정**이 들어간다. 따라서 **27M 파라미터라는 사실만으로 전체 추론 비용이 작다고 할 수 없다.** 모든 평가 과제가 같은 방식을 쓰는 것도 아니므로 과제별 조건을 확인해야 한다. [arxiv.org](https://arxiv.org/html/2506.21734v3)

TRM이 중요한 이유도 여기에 있어.

**“뇌처럼 두 층을 나눴다”, “모듈이 여러 개다”보다 반복 계산 방식과 학습 방법이 성능의 실제 원인일 수 있다.** 그래서 우리도 반드시 **단일 작은 순환망 vs 여러 모듈**을 비교해야 해. 여러 개를 연결했다는 사실 자체를 성공으로 삼으면 안 된다.

# 4. Hugging Face 모델: 실제 역할 적합성으로 추린 후보

## 4-1. 입력 이해와 유한 선택: 여기서는 작은 생성형 LLM이 필수는 아니다

이 분야는 생각보다 후보가 다양했어. 특히 **문장을 생성하지 않고 구조나 선택 결과를 반환하는 모델**이 네 목적에 잘 맞는다.

|---|---:|---|---|
| **`jhu-clsp/mmBERT-small`** | 약 140M | 다국어 마스크 언어 모델 | **직접 튜닝할 공통 인코더의 우선 후보.** 기본 상태가 완성된 판단기는 아니다. [Hugging Face](https://huggingface.co/jhu-clsp/mmBERT-small) |

| **`fastino/GLiNER2.5-multi-Decide`** | 약 287M | 동적 라벨 기반 분류·판단 | **Julia와 비교할 라우팅 후보.** 일반 추론기나 계획 생성기로 취급하지 않는다. [Hugging Face](https://huggingface.co/fastino/GLiNER2.5-multi-Decide) |

| **`klue/roberta-base`** | 약 111M | 한국어 사전학습 | 한국어 전용 분류·근거 검증 헤드를 학습할 비교군. [Hugging Face](https://huggingface.co/klue/roberta-base) |

### mmBERT-small: ‘작은 뇌를 직접 튜닝한다’면 가장 먼저 볼 후보

이 모델의 장점은 **이미 모든 판단을 잘한다는 것**이 아니라, 우리가 필요한 역할을 학습시킬 **작은 다국어 표현 기반**이라는 점이야.

주의할 것은 파라미터 집계야. 카드의 **약 42M은 임베딩을 제외한 수치**이고, 전체는 약 140M이다. 작은 수치만 보고 메모리를 계산하면 안 된다. 한국어를 포함한 다국어 학습 범위도 확인되지만, 그것이 특정 한국어 과제의 정확도를 보장하지는 않는다. [Hugging Face](https://huggingface.co/jhu-clsp/mmBERT-small)

내가 이걸 쓰는 방식은 별도 모델을 여러 개 복제하는 것보다:

> **공유 인코더 → 의도 분류 헤드 / 정정 감지 헤드 / 근거 관계 헤드 / 행동 후보 평가 헤드**

를 먼저 시험하는 거야.

여러 기능의 표현을 공유하는 구성과 독립 모델 구성을 비교해야, **정말로 ‘분리’가 도움이 되는지** 알 수 있다.

### Julia-1: 한국어 근거는 있지만, 평가 범위를 정확히 읽어야 한다

공개 평가 원자료에서 한국어 MASSIVE 결과는 **2,974개 중 2,296개 정답, 약 77.20%**야. 다만 모델 카드가 명시하는 평가 대상은 **18개 상황 분류**다. 이를 전체 의도 분류·슬롯 추출·일반 추론 성능으로 확대하면 안 된다. [Hugging Face](https://huggingface.co/SupersonicLabs/Julia-1/blob/main/metrics/accuracy-20260924.json)

또한 기본 선택지 범위가 **2–20개**이고, 자체 런타임을 사용한다. 가중치와 추론 코드가 공개되어 있지만 전체 학습 파이프라인은 공개되지 않았다는 제약도 있다. [Hugging Face](https://huggingface.co/SupersonicLabs/Julia-1)

그래서 내 평가는:

> **고정된 행동 후보 중 하나를 선택하는 초기 기준선으로는 적합.  
> 우리가 원하는 인지 기능으로 자유롭게 재학습할 핵심 기반으로는 제약이 있음.**

이야.

### GLiNER2.5: 현재 목적에는 꽤 잘 맞지만, 한국어는 별도 검증

다국어 추출 모델은 엔티티뿐 아니라 관계·구조화 정보·분류를 함께 다룬다. 따라서 처음부터 **추출 모델 하나 + 라우터 하나**를 둘 필요 없이, **한 모델로 어디까지 되는지** 시험할 가치가 있다. [Hugging Face](https://huggingface.co/fastino/gliner2.5-multi-v1)

Decide 다국어판도 출력 형식은 목적에 잘 맞아. 하지만 대표 공개 비교표는 **영어 17개 도메인**이다. 이 점수를 한국어 성능으로 가져올 수는 없다. [Hugging Face](https://huggingface.co/fastino/GLiNER2.5-multi-Decide)

그리고 엔티티를 잘 찾는 것과 상황을 이해하는 것은 달라.

예를 들어:

> “A가 B를 승인한 게 아니라, B가 A의 요청을 거절했어.”

여기서 A와 B를 정확히 추출해도 **행위 주체, 부정, 관계 방향**을 잘못 읽으면 인지 코어에 틀린 상태가 들어간다. 그래서 추출 F1만 볼 게 아니라 **상태 변환의 정확도**를 평가해야 한다.

### Laya: 이번에 가장 신중하게 봐야 했던 사례

저자 공개 평가 문서의 typed-decisions 결과는 다음과 같아.

| 조건 | 저자가 보고한 정확도 |
|---|---:|
| 기본 영어 Laya | 36.2% |
| 다수 클래스 기준선 | 46.1% |
| 별도 `laya-typed-decisions` 튜닝판 | 76.6% |

같은 문서는 **튜닝판의 해당 결과를 뒷받침하는 공개 결과 파일이 아직 없다고 명시**한다. 따라서 “Laya 76.6%”라는 숫자만 보고 기본 체크포인트를 내려받으면 잘 작동할 것이라고 기대하면 안 된다. [GitHub](https://github.com/NandhaKishorM/laya/blob/main/BENCHMARKS.md)

이것을 “Laya는 나쁜 모델”로 해석하는 것도 부정확해. 내가 내리는 결론은 **아키텍처의 가능성과 특정 체크포인트의 적용 성능을 분리해야 한다**는 거야.

지금은 기본 모델을 인지 코어로 확정하기보다, **우리 과제에 튜닝했을 때 얼마나 나아지는지 검증할 연구 후보**로 두는 편이 맞다.

## 4-2. 기억 검색: Qwen 0.6B가 무조건 첫 선택은 아니다

우리 시스템의 기억이 처음부터 수십 페이지 문서일 필요는 없어. “누가 무엇을 말했다”, “규칙이 언제 변경되었다” 같은 짧은 사건이 중심이라면 작은 모델부터 시험하는 것이 합리적이야.

| 후보 | 규모 / 입력 길이 | 적합한 사용 조건 | 내 우선순위 |
|---|---|---|---|
| **`intfloat/multilingual-e5-small`** | 약 118M / 512토큰 | 짧게 분리한 대화 사건·경험 검색 | **경량 기준선**. 긴 입력을 잘라버리지 않도록 사건 단위 저장 필요. [Hugging Face](https://huggingface.co/intfloat/multilingual-e5-small/blob/main/README.md) |
| **`google/embeddinggemma-300m`** | 약 300M / 2,048토큰 | 온디바이스 다국어 검색 | E5 다음의 **주요 비교 후보**. Gemma 이용 조건 확인. [Hugging Face](https://huggingface.co/google/embeddinggemma-300m) |
| **`Alibaba-NLP/gte-multilingual-base`** | 약 305M / 8,192토큰 | 조금 긴 경험 기록·문서 검색 | 긴 문맥이 실제로 필요할 때 비교. [Hugging Face](https://huggingface.co/Alibaba-NLP/gte-multilingual-base) |
| **`Qwen/Qwen3-Embedding-0.6B`** | 약 596M / 32K | 긴 입력·지시 기반 검색 | 짧은 기억에서 추가 비용만큼 이익이 있는지 확인 후 채택. [Hugging Face](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B) |
| **`BAAI/bge-m3`** | 약 568M / 8,192토큰 | dense·sparse·multi-vector 혼합 검색 | 검색 방식의 복잡성이 필요한 경우에만. [Hugging Face](https://huggingface.co/BAAI/bge-m3) |

**내 초기 선택은 E5-small과 EmbeddingGemma의 비교**야. 가장 유명해서가 아니라, 지금 가정한 **짧은 한국어 경험 검색**이라는 역할에 맞춰 작은 것부터 검증하기 위해서다.

다만 검색 모델은 어디까지나 **기억을 찾는 부품**이야. 실제 기억 시스템에는 별도로 다음 정보가 있어야 한다.

> 원문, 발생 시각, 출처, 현재 유효한지, 정정 관계, 어떤 결론의 근거로 사용되었는지.

“전에 그렇게 말했지만 지금은 아니야”라는 정정을 처리하지 못하면, 임베딩 성능이 좋아도 기억 시스템은 틀린다.

## 4-3. Reranker: 기억 후보를 고르는 데는 적합하지만, 제어기는 아니다

| 후보 | 규모 | 적합성 판단 |
|---|---:|---|
| **`Alibaba-NLP/gte-multilingual-reranker-base`** | 약 306M | 한국어를 포함한 다국어 관련도 비교의 우선 후보. [Hugging Face](https://huggingface.co/Alibaba-NLP/gte-multilingual-reranker-base) |
| **`Qwen/Qwen3-Reranker-0.6B`** | 약 596M | 지시 기반 관련도 평가 후보. CausalLM의 yes/no 로짓을 사용하는 구조다. [Hugging Face](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B) |
| **`jinaai/jina-reranker-v2-base-multilingual`** | 약 278M | 기능상 후보지만, 공개 라이선스가 CC-BY-NC-4.0이므로 향후 사용 범위를 확인해야 한다. [Hugging Face](https://huggingface.co/jinaai/jina-reranker-v2-base-multilingual) |
| **`BAAI/bge-reranker-v2-m3`** | 약 568M | 다국어 비교군. 작은 시스템에서는 메모리 대비 개선이 있는지 확인. [Hugging Face](https://huggingface.co/BAAI/bge-reranker-v2-m3) |

여기서는 **GTE reranker부터 비교하되, 처음부터 필수 부품으로 넣지는 않겠다.**

검색된 기억이 적고 상태 구조가 명확하면, reranker 없이도 충분할 수 있어. 추가 모델 하나를 넣을 때마다 **실패가 얼마나 줄고 비용이 얼마나 늘었는지** 보여야 한다.

그리고 중요한 수정 하나.

**기억 30개 중 3개를 고르는 것 자체가 새로운 인지 구조는 아니야.** 이것은 재순위화가 붙은 검색 파이프라인으로도 할 수 있다. 인지 코어의 연구 지점은 **그 3개를 이후에도 유지할지, 새로운 관측으로 교체할지, 언제 다시 읽을지**에 있다.

## 4-4. 검증 모델: ‘좋아 보임’과 ‘맞음’을 분리해야 한다

내가 앞서 Skywork reward를 Critic의 기본값으로 둔 것은 수정하는 게 맞아.

| 검증하려는 것 | 후보 | 실제로 판단하는 것 | 한계 |
|---|---|---|---|
| 근거에서 주장이 따라오는가 | **`MoritzLaurer/mDeBERTa-v3-base-mnli-xnli`** | 함의·모순·중립 | 다국어 기반이지만 공개 XNLI 지도학습 언어에 한국어가 없어 별도 한국어 검증이 필요하다. [Hugging Face](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-mnli-xnli) |
| 제공된 문서가 답변을 지지하는가 | **`vectara/hallucination_evaluation_model`** | 근거 지지 평가 | 공개 HHEM-2.1-Open과 별도 플랫폼의 후속 다국어 모델을 혼동하면 안 된다. [Hugging Face](https://huggingface.co/vectara/hallucination_evaluation_model) |
| 두 답변 중 무엇이 선호되는가 | **`Skywork-Reward-V2-Qwen3-0.6B`** | 응답 선호·품질 | 세계의 진실이나 장기 행동 가치가 아니다. [Hugging Face](https://huggingface.co/Skywork/Skywork-Reward-V2-Qwen3-0.6B) |
| 코드 후보의 품질은 어떤가 | **`Themis-RM-0.6B`** | 코드의 여러 품질 기준에 따른 평가 | 실제 실행·테스트·정적 검사를 대체하지 않는다. [Hugging Face](https://huggingface.co/project-themis/Themis-RM-0.6B) |

이 프로젝트에는 **일반 응답 reward보다 근거 관계 검증이 더 가까운 역할**이라고 봐.

한국어 중심으로 직접 튜닝한다면 `klue/roberta-base` 또는 mmBERT에 **근거 → 주장 관계를 판정하는 헤드**를 학습시키는 것도 좋은 비교군이다. 한국어 부품 평가에는 KLUE의 NLI·관계 추출·대화 상태 추적 같은 과제를 활용할 수 있다. [arXiv](https://arxiv.org/abs/2105.09680)

다만 이것도 만능 사실 검증기는 아니야.

> 잘못된 문서가 “A는 B다”라고 말하고 있을 때,  
> NLI 모델은 “이 문서는 A가 B라는 주장을 지지한다”고 올바르게 판단할 수 있다.

**근거의 신뢰성과 근거에서 결론이 따라오는지는 별도로 관리해야 한다.**

## 4-5. 생성 모델은 필요할 때만 ‘후보 제안자’로

유창한 답변이 없어도 된다면 처음에는 생성 모델을 빼도 돼.

다만 **정해진 선택지에 없는 가설이나 새로운 계획을 구성해야 할 때**는 방법이 필요하다. 그것이 꼭 LLM일 필요는 없지만, 규칙 기반 탐색·계획기·학습된 행동 시퀀스 생성기 중 무언가는 있어야 해.

생성형 부품을 추가한다면 현재 비교할 만한 후보는 다음 정도야.

**`LiquidAI/LFM2.5-1.2B-Instruct`**는 약 1.17B의 텍스트 모델이고, 한국어를 지원 언어로 명시한다. 작은 구조화 후보 제안기의 비교 대상으로 적합하다. 다만 별도 LFM 라이선스를 확인해야 하고, 우리 장비에서의 지연은 직접 측정해야 한다. [Hugging Face](https://huggingface.co/LiquidAI/LFM2.5-1.2B-Instruct)

**`Qwen/Qwen3.5-2B`**는 좀 더 큰 후보 생성 기준선으로 둘 수 있다. 모델 이름의 언어 모델 크기와 비전 등을 포함한 전체 저장 규모는 구분해야 하며, 텍스트 전용 실행 방식도 확인할 수 있다. [Hugging Face](https://huggingface.co/Qwen/Qwen3.5-2B)

내가 이 모델들에 맡길 역할은:

> “최종 결정을 내려라”가 아니라  
> **“현재 상태에서 가능한 다음 계획 세 개를 제안하라.”**

야.

그다음 채택 여부는 상태·근거·제약·실행 결과로 판단하게 만든다.

# 5. 실제로 만들 구조: 두 단계로 나누는 게 좋다

## 5-1. 먼저, 학습 없이 동작하는 기준 시스템

첫 시스템은 다음 정도면 충분해.

| 기능 | 초기 구성 |
|---|---|
| 입력 구조화 | GLiNER2.5 다국어 추출 모델과 간단한 규칙 파서 비교 |
| 즉시 판단 | Julia-1 또는 GLiNER2.5-multi-Decide 중 하나 |
| 경험 검색 | E5-small, 이후 EmbeddingGemma와 비교 |
| 기억 저장 | 사건·출처·시간·정정 관계를 가진 명시적 저장소 |
| 진행 제어 | 작은 상태 머신 |
| 검증 | 명시적 규칙 검사 + 필요한 경우 근거 관계 모델 |
| 출력 | 행동 ID, 선택 결과, 상태 요약 템플릿 |

**이 단계는 학습된 ‘뇌’라고 부르기보다, 모듈식 인지 시스템의 기준선으로 보는 게 맞아.**

그래도 충분히 의미가 있다. 입력 해석 오류인지, 검색 오류인지, 상태 갱신 오류인지 분리해서 볼 수 있으니까.

그리고 **위 표의 모델을 모두 탑재하자는 뜻은 아니다.** 추출 모델의 분류 기능만으로 충분하면 Julia를 빼고, 단순 검색만으로 충분하면 reranker를 빼는 식으로 줄여야 한다.

## 5-2. 그다음, 작은 인지 코어를 학습한다

여기부터가 네 아이디어의 핵심이야.

코어의 입력은 전체 대화 원문만이 아니라:

> 현재 목표, 새 관측, 유지 중인 작업기억, 검색 결과, 이전 행동 결과, 남은 계산 예산

으로 구성한다.

출력은 처음에는 다음처럼 제한하면 돼.

| 코어가 선택할 것 | 의미 |
|---|---|
| **유지** | 기존 작업기억을 그대로 둔다 |
| **기록·교체** | 새 정보로 기억 일부를 갱신한다 |
| **검색** | 장기기억에서 추가 근거를 가져온다 |
| **계산·검증** | 특정 전문 부품을 실행한다 |
| **행동** | 환경에서 다음 동작을 수행한다 |
| **보류·질문** | 현재 정보로는 결정할 수 없음을 표시한다 |
| **종료** | 더 계산하지 않고 결과를 확정한다 |

처음부터 거대한 모델이 필요하다는 근거는 없어. **작은 단일 GRU 같은 순환망을 기준선으로 두고, RIMs처럼 여러 상태 모듈을 둔 구조와 비교**하는 편이 좋다. 작은 순환 모듈의 선택적 업데이트라는 발상은 RIMs와 직접 연결되지만, 우리 환경의 제어 정책은 새로 학습해야 한다. [arXiv](https://arxiv.org/abs/1909.10893)

여기서 학습 목표는 “좋은 말을 했는가”가 아니야.

**목표를 달성했는가, 필요한 기억을 보존했는가, 정정을 반영했는가, 불필요한 계산을 줄였는가**가 되어야 한다.

또한 유한 행동을 반복 선택하는 것만으로도 **새로운 행동 조합**을 만들 수 있다. 다만 이것은 준비된 기본 행동들을 조합하는 능력이지, 아직 정의되지 않은 새로운 행동까지 자동으로 발명하는 능력은 아니다.

# 6. 가장 어려운 부분은 모델 연결보다 ‘표현과 상태’다

## 서로 다른 모델의 벡터는 그냥 연결하면 통하지 않는다

E5의 벡터와 mmBERT의 은닉 상태, Qwen의 은닉 상태는 **차원 수가 같아도 의미가 정렬되어 있다는 보장이 없다.**

Global Latent Workspace 제안이 중요한 이유가 바로 이것이야. 서로 다른 전문 시스템의 표현을 공통 공간으로 번역하는 과정 자체가 연구 대상이다. [arXiv](https://arxiv.org/abs/2012.10390)

따라서 두 접근을 구분해야 한다.

**첫 번째는 명시적 상태 공유.**  
원문 위치, 대상 ID, 관계, 시각, 관측·가설 여부 같은 구조를 정해서 전달한다. 처음 구현하고 오류를 추적하기에는 이쪽이 낫다.

**두 번째는 학습된 잠재공간 공유.**  
모델별 표현을 작은 어댑터로 변환하고, 같은 사건에 대한 표현과 과제 수행 결과를 이용해 정렬한다. 이것이 더 신경망적인 방식이지만, 별도의 학습 데이터와 목적함수가 필요하다.

처음부터 두 번째로 가면 **입력 해석 실패인지, 표현 정렬 실패인지, 제어 실패인지** 구분하기 어려워져. 그래서 나는 첫 번째를 먼저 만들고, 이후 일부 통신 경로만 잠재공간으로 바꾸는 실험을 권한다.

## 공통 workspace는 ‘로그 창’과 달라야 한다

모든 모델 출력을 한 화면에 보여준다고 공유 인지 공간이 생기는 것은 아니야.

**앞선 모듈이 기록한 상태가 다음 모듈의 입력·활성화·계산을 바꿔야 한다.**

Shared Workspace 연구에서 가져올 핵심도 제한된 공간과 모듈 간 정보 전달이 실제 계산 과정에 들어간다는 점이지, 중앙에 큰 텍스트 저장소가 있다는 사실이 아니다. [arxiv.org](https://arxiv.org/html/2103.01197v2)

## 점수들을 한 줄로 평균 내면 안 된다

다음 네 값은 전부 0과 1 사이로 표현할 수 있어도 의미가 달라.

> 검색 관련도 0.9  
> 응답 선호 점수 0.9  
> 근거 지지 점수 0.9  
> 행동 성공 예측 0.9

이걸 평균 내서 “확신 90%”라고 만들면 안 된다.

분류기의 softmax도 실제 정답 확률과 일치한다는 보장이 없고, 보정한 확률도 새로운 분포에서 무너질 수 있다. **확률 보정, 새로운 과제에서의 오류, 보류 판단을 각각 시험해야 한다.** [arXiv](https://arxiv.org/abs/1706.04599)

# 7. 무엇으로 시험해야 ‘인지 시스템’이라고 말할 수 있을까

내가 첫 실험으로 고를 것은 **대화로 규칙이 주어지고, 중간에 정보가 바뀌는 작은 가상 환경**이야.

예를 들면:

> 처음에는 파란 열쇠가 A문을 연다.  
> 중간에 다른 과제와 방해 정보가 들어온다.  
> 이후 “규칙이 바뀌어서 이제 A문은 빨간 열쇠로만 열린다”고 정정한다.  
> A문 뒤의 물건을 가져오라는 목표를 준다.

최종 출력은 문장이 아니라 **열쇠 선택 → 이동 → 문 열기 → 물건 획득** 같은 행동이면 된다.

이 실험에서 관찰할 것은 말솜씨가 아니야.

| 시험할 능력 | 일부러 만들어야 할 상황 |
|---|---|
| **작업기억 유지** | 지금 당장은 필요 없지만 몇 단계 뒤 필요한 정보 |
| **정정 반영** | 이전 사실과 충돌하는 최신 관측 |
| **선택적 검색** | 비슷하지만 행동에는 도움이 안 되는 기억 |
| **계획** | 최종 목표 전에 해결해야 하는 선행 조건 |
| **조합 일반화** | 각각 본 적 있는 규칙을 처음 보는 조합으로 제시 |
| **불확실성 처리** | 정답에 필요한 정보가 없거나 서로 모순되는 상황 |
| **연산 절약** | 간단한 문제에서는 검색·추론을 생략해도 되는 상황 |

특히 **한국어 입력 해석과 코어의 인지 능력은 분리 평가**해야 해.

같은 과제를 한 번은 정답 구조화 상태로 코어에 주고, 한 번은 한국어 문장을 거쳐 주는 거야. 전자에서는 잘하는데 후자에서 실패한다면, 원인은 ‘추론 능력 부족’보다 입력 파서일 수 있다.

이 구분 없이 최종 성공률 하나만 보면 어디를 고쳐야 하는지 알 수 없어.

## 반드시 있어야 하는 비교군

| 비교군 | 확인하는 질문 |
|---|---|
| **규칙 기반 제어 + 같은 전문 부품** | 학습된 제어기가 실제로 필요한가? |
| **작은 단일 순환망** | 여러 모듈로 나누는 것이 정말 도움이 되는가? |
| **공유 인코더 + 여러 헤드** | 독립 모델 여러 개보다 표현 공유가 더 효율적인가? |
| **RIMs·공유 workspace 코어** | 선택적 갱신과 통신이 일반화를 개선하는가? |
| **단일 소형 LLM + 같은 기억·도구** | 복잡한 구조가 단순한 생성 모델보다 유리한 영역은 어디인가? |

비교할 때는 같은 지식과 도구를 주고, **호출 횟수·반복 횟수·총 지연·학습 데이터·테스트 시 추가 계산**을 함께 기록해야 한다.

모델 수만 맞추거나 파라미터 수만 맞추는 것으로는 부족하다. HRM의 증강 투표처럼 테스트 시 계산이 큰 경우도 있고, 작은 모델 여러 개의 반복 호출이 단일 모델 한 번보다 비싸질 수도 있기 때문이야. [arxiv.org](https://arxiv.org/html/2506.21734v3)

또한 모듈을 하나씩 끄는 실험이 필요해.

**기억 모듈을 껐는데 성능이 그대로면 그 과제는 기억을 시험하지 않았거나, 다른 경로가 기억을 대신하고 있는 것**이다. 이처럼 실제 기여를 확인해야 ‘뇌 부품’이라는 이름이 아니라 기능으로 설명할 수 있다.

# 8. 로컬 실행과 튜닝에서 지켜야 할 조건

현재 실험 장비를 하나로 확정하지 않았으니 **8GB와 16GB VRAM 조건을 나눠 계획하는 편**이 좋겠어. 아래는 측정값이 아니라 배치 전략이다.

**8GB 조건**에서는 작은 인코더·검색 모델을 우선 두고, 생성 모델은 하나만 필요할 때 사용하거나 CPU와 역할을 나누는 식으로 시작하겠다. 긴 문맥과 여러 생성 모델의 동시 상주는 피한다.

**16GB 조건**에서는 더 큰 비교군이나 여러 부품의 상주를 시험할 수 있지만, 그래도 모델 개수를 늘리기 전에 병목을 측정해야 한다.

가중치 용량의 이론적 출발점은:

\[
\text{가중치 바이트 수}\approx
\frac{\text{파라미터 수}\times\text{비트 수}}{8}
\]

이지만, 이것은 **실제 실행 메모리 총량이 아니야.** 활성값·캐시·배치·작업 버퍼·런타임이 추가된다. 한 GPU에서 동시에 실행한다고 논리적 병렬성이 그대로 속도 향상이 되는 것도 아니다.

튜닝에서도 전부 LoRA부터 걸 필요는 없다. 역할별 분류 헤드, 작은 어댑터, 코어만 학습하는 방법을 각각 비교하면 된다. 다만 Julia처럼 학습 파이프라인 공개 범위가 제한된 모델과, 우리가 헤드를 붙일 기본 인코더는 재학습 편의성이 다르다. [Hugging Face](https://huggingface.co/SupersonicLabs/Julia-1)

배포 조건도 선택에 들어가야 해. 예를 들어 Jina reranker의 공개 라이선스, Gemma 이용 조건, LFM의 별도 라이선스는 서로 같지 않다. **로컬에서 실행 가능하다는 사실과 모든 용도로 자유롭게 사용할 수 있다는 것은 별개**다. [Hugging Face](https://huggingface.co/jinaai/jina-reranker-v2-base-multilingual)

# 9. 그래서 지금 무엇을 선택하겠냐면

나는 **‘모델 다섯 개를 먼저 다운로드’하는 대신 다음 구성을 실험 후보로 고정**하겠어.

| 위치 | 우선 선택 | 선택 이유 |
|---|---|---|
| **입력 구조화** | GLiNER2.5 다국어 추출 모델 | 생성 없이 엔티티·관계·구조화 정보를 얻는 목적에 가까움 |
| **즉시 선택 판단** | Julia-1 vs GLiNER2.5-multi-Decide | 실제 후보 선택 기능을 학습한 모델끼리 비교 |
| **짧은 경험 검색** | E5-small vs EmbeddingGemma | 짧은 한국어 사건 검색에서 크기 대비 성능 확인 |
| **직접 튜닝할 표현 기반** | mmBERT-small | 공통 인코더와 여러 역할별 헤드를 만들기 위한 후보 |
| **인지 코어** | 작은 단일 순환망 → RIMs 비교 | 기억 유지·갱신·호출·중단을 과제 결과로 학습 |
| **검증** | 명시적 제약 검사 + 한국어 근거 관계 모델 | 응답 선호보다 근거·규칙 일치가 현재 목적에 가까움 |
| **생성 부품** | 첫 실험에서는 제외 | 필요할 때만 LFM2.5-1.2B 또는 Qwen3.5-2B를 후보 제안자로 추가 |

표의 후보를 모두 한 시스템에 넣는 것은 아니야. **겹치는 기능은 경쟁시켜 하나를 남기고, 기여가 없는 부품은 빼는 구성**이다.

반대로 초기에는 다음을 보류하겠다.

**Skywork RM을 범용 사실 판정기로 쓰는 것, HRM·TRM 체크포인트를 자연어 추론기로 간주하는 것, 영어 중심 모델의 점수를 한국어 성능으로 옮기는 것, 모든 모델을 매번 깨우는 것.** 각각 학습 목적·입력 형식·평가 범위가 현재 역할과 맞지 않거나 추가 검증이 필요하다. [Hugging Face](https://huggingface.co/Skywork/Skywork-Reward-V2-Qwen3-0.6B)

## 최종 판단

**네 아이디어의 핵심은 충분히 연구할 만하다. 하지만 새로운 점은 ‘여러 AI가 있다’가 아니라, ‘그 여러 AI를 어떻게 써야 하는지 시스템이 학습한다’에 있어.**

기억·제어·전문 모듈을 결합하는 인지 아키텍처 자체는 이미 오랜 선행 연구가 있으므로, 부품을 붙였다는 이유만으로 새로운 구조라고 주장하기는 어렵다. [AAAI Publications](https://ojs.aaai.org/aimagazine/index.php/aimagazine/article/view/2744)

대신 다음 질문은 구체적이고 검증 가능해.

> **한국어 텍스트를 이해하는 경량 전문 모델들을 고정해 둔 상태에서, 작은 순환 제어망이 기억 갱신과 모듈 호출을 학습하면, 같은 계산 예산의 단일 모델이나 고정 파이프라인보다 새로운 규칙 조합과 정보 정정에 잘 대응하는가?**

이 질문으로 가면 결과가 어느 쪽으로 나오든 의미가 있어. 여러 모듈이 이기면 **어떤 상호작용이 이득을 만들었는지** 설명할 수 있고, 단일 작은 코어가 이기면 **불필요한 분리를 제거한 더 나은 구조**를 얻는다.

**지금 먼저 만들 것은 ‘말 잘하는 작은 뇌 여러 개’가 아니라, `기억을 유지하고, 틀린 상태를 고치고, 필요한 계산만 선택하는 작은 시스템`이야.** 이번 조사에서는 그쪽이 네 의도와 가장 잘 맞았다.

전체 후보의 정확한 저장소, 보류 이유, 논문별 적용 원리와 한계는 local_cognitive_system_research_2026-10-05.md[모델·논문 조사 노트](sandbox:/mnt/data/local_cognitive_system_research_2026-10-05.md)에 정리해 두었다.
